Access policies

v1 · 15 Nov 2026, 6:20 PM AEDT

This page walks the Fabric Access Policies chain: the fabric-side setup that lets a leaf port carry VLANs into a tenant EPG. It is drawn from two photographs of a DevLab / sandbox ACI (Leaf Profile L-101_L102, Interface Policy Group Port_Std_ESXi_Host, VLAN pool ESXi_VLP 300–399). Those names are not from ARR-FABRIC. The ARR cross-check at the bottom uses a NetBox export and the Cursor_Tenant6 v4 post-check files already on the box. No APIC was contacted for this page.

How to read the chain. You usually build it from the bottom (global) up, then attach ports:

  • A VLAN pool holds the encapsulation range.
  • A physical domain points at that pool.
  • An AAEP points at the domain.
  • An interface policy group points at the AAEP and at interface policies (Link Level, LLDP, and so on).
  • A leaf interface profile has a port selector and port block, which point at the policy group.
  • A leaf switch profile selects the leaf nodes and points at the interface profile. A switch policy group can hang off the association for STP or BFD.
  • A tenant EPG then uses fvRsDomAtt to the same physical domain, and fvRsPathAtt to a concrete leaf port, so the VLAN on that port is valid.

Plain-English walkthrough

The source diagram is organised as three bands, top to bottom: Switch policies, Interface policies, and Global policies. The numbered circles are GUI menu counts on that sandbox fabric, not counts from ARR.

1. Switch policies

The Leaf Profile L-101_L102 (infra:NodeP) uses a Switch Association whose node block covers leaves 101–102 (infra:LeafS and infra:NodeBlk, with from_ / to_). That association can point at the Leaf Policy Group Default_SPG (infra:AccNodePGrp), which in the notes holds the default STP and BFD policies. The profile also points at the interface profile in the next band, through infra:RsAccPortP.

2. Interface policies

The Leaf Interface Profile L101_L102_IPR (infra:AccPortP) contains the access port selector Eth1_1-5 (infra:HPortS) and a port block for eth1/1–5 (infra:PortBlk). The selector links through infra:RsAccBaseGrp to the Interface Policy Group Port_Std_ESXi_Host (infra:AccPortGrp). That group is a regular access (non-channel) group. A port-channel or VPC group would be infra:AccBndlGrp instead. The group uses the Link Level policy 10Gb_INTPOL (fabric:HIfPol) and the LLDP policy LLDP_Enable_INTPOL (lldp:IfPol).

3. Global policies

The policy group points at the AAEP PHY_AEP (infra:AttEntityP). The AAEP points at the Physical Domain Standalone_ESXi_PHY (phys:DomP), which uses the VLAN pool ESXi_VLP (fvns:VlanInstP), allocation static, range 300–399.

The YAML snippets on the notes are the Ansible modules that build step 2: cisco.aci.aci_interface_policy_leaf_policy_group makes the group (5), and cisco.aci.aci_access_port_to_interface_policy_leaf_profile makes the selector and port block (6/7). The port list (SnV_server2 1/1, Heroes_corporate_external 1/47, and so on) shows other interface profiles mapped the same way. Those profile names match the published simulator (Heroes / SnV) access_policies.nac.yaml, not ARR-FABRIC.

Ansible and nac-aci YAML

The Ansible below follows the official cisco.aci module options and the names from the notes. The login secret is the placeholder {{ apic_password }}. The port-block name eth1-5 was not independently labelled on the notes; the range eth1/1–5 was. A PC or VPC group would set lag_type: link or lag_type: node and would create infra:AccBndlGrp.

---
# DevLab example that builds step 5 (the access port policy group)
# and steps 6/7 (the selector and port block) from the source notes.
# These names are from the sandbox chain, not from ARR-FABRIC.
# The login secret is a placeholder. Do not put a real value here.

- name: Create the leaf access port policy group (5)
  cisco.aci.aci_interface_policy_leaf_policy_group:
    host: "{{ apic_host }}"
    username: "{{ apic_username }}"
    password: "{{ apic_password }}"
    validate_certs: false
    lag_type: leaf
    policy_group: Port_Std_ESXi_Host
    link_level_policy: 10Gb_INTPOL
    lldp_policy: LLDP_Enable_INTPOL
    aep: PHY_AEP
    state: present
  delegate_to: localhost

- name: Associate Eth1_1-5 on L101_L102_IPR with that group (6/7)
  cisco.aci.aci_access_port_to_interface_policy_leaf_profile:
    host: "{{ apic_host }}"
    username: "{{ apic_username }}"
    password: "{{ apic_password }}"
    validate_certs: false
    interface_profile: L101_L102_IPR
    access_port_selector: Eth1_1-5
    port_blk: eth1-5
    from_port: "1"
    to_port: "5"
    policy_group: Port_Std_ESXi_Host
    state: present
  delegate_to: localhost
