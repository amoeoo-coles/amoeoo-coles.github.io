Overview

PseudoBank is a small retail-banking HTTP API used as a reference workload for CI/CD and GitOps on Red Hat OpenShift. The README describes it as internal demonstration material, not for production use. The image path in the Deployment points at the OpenShift namespace sng669995, which matches the AI Pod / OpenShift demo project.

The HTTP layer is Flask 3.0.3 behind gunicorn 22.0.0 (two sync workers). Domain logic lives in an in-memory Ledger that uses decimal.Decimal, enforces an overdraft floor, and writes a journal. Seed data is four fictitious sterling accounts. The OpenShift set is a Deployment (two replicas), a Service, and a Route with edge TLS and HTTP-to-HTTPS redirect.

The code is generally tidy for a demo: money is not stored as float, overdraft is honoured, and ledger exceptions are mapped to HTTP status codes. The serious problems are a server-side request forgery hook, unauthenticated transfers (including a cookie-as-IBAN shortcut), and four split in-memory ledgers once the documented gunicorn worker count and Deployment replica count are combined.

Architecture

Four independent ledgers in this layout: 2 replicas x 2 workers. There is no shared store.

SeverityFindingWhy it mattersRecommended fix
HighSSRF on POST /api/v1/webhooks/verifyThe handler calls requests.get(callbackUrl, timeout=5) on a caller-supplied URL with no scheme or host allowlist and no block of private, link-local or metadata addresses. From an OpenShift pod this can probe in-cluster services and, on some platforms, cloud metadata. This is the only use of the requests import. The route is not in the README.Remove the route, or allowlist destinations, deny private/metadata ranges, disable redirects, and do not follow user URLs from the cluster network.
HighNo authentication on POST /api/v1/transfersAnyone who can reach the OpenShift route can move funds between any seeded accounts and read balances and the journal. The README presents this as a core-banking API; the licence says it is demonstration material, but the Route still exposes it.Put the route on a private network, or add real authentication and authorisation (and CSRF protection) before it is reachable.
HighCookie value used as the source IBAN on /transfers/quickrequest.cookies.get("pseudobank_session") is passed straight to ledger.transfer as the debit account. Setting that cookie to another holder’s IBAN debits their account. The endpoint accepts form posts and has no CSRF token, so a third-party page can drive it in a browser. Also absent from the README.Do not treat a cookie as an IBAN. Require a real session or identity, bind the debit account to that identity, and add a CSRF token — or delete the route.
HighIn-memory ledger with 2 gunicorn workers and 2 replicasEach worker process has its own Ledger created at import. Two replicas times two workers is four independent ledgers. Balances and the journal diverge; a transfer can succeed on one worker and be invisible on the next request. /readyz only reports the in-process account count.Use a shared store (for example PostgreSQL) with a transactional debit/credit, or run a single replica and a single worker if the ledger must stay in memory. Add a lock around transfer inside a process.
MedTwo routes are defined after app.run()In app.py, if __name__ == "__main__": app.run(...) sits above the webhook and quick-transfer view functions. Under make run / python app.py those functions are not registered until the server exits. Gunicorn imports the module and does register them. Local and production attack surface therefore differ.Move every route decorator above the __main__ block.
Medrequests==2.32.3 is affected by CVE-2024-47081Versions before 2.32.4 can leak .netrc credentials to a third party for a crafted URL. The official fix is 2.32.4. Because this app already fetches a caller-supplied URL, the CVE is more relevant here than in a typical requests user, even if a UBI image may not ship a .netrc.Upgrade to requests>=2.32.4, set trust_env=False, and fix or remove the SSRF route.
MedUnpinned :latest image tagsThe Dockerfile is registry.access.redhat.com/ubi9/python-311:latest. The Deployment pulls image-registry.openshift-image-registry.svc:5000/sng669995/pseudobank:latest. Builds and rollouts are not reproducible, and a bad build can be served without a tag change.Pin the base image to a digest (or a dated tag) and deploy an immutable app image tag or digest.
LowFlask==3.0.3 is affected by CVE-2026-27205Flask before 3.1.3 can omit the Vary: Cookie header for some session-access paths, which can let a poorly configured cache store a user-specific response. This app does not use Flask’s session object, so practical risk is low. CVE-2025-47278 (fallback signing key) does not affect 3.0.3; it only affects 3.1.0.Upgrade to Flask 3.1.3 or later.
LowSame-account transfers are acceptedA local check with the ledger showed transfer(src, src, "10.00") journals a 10.00 payment and leaves the balance unchanged. That can pad a journal or confuse a reconciliation demo.Reject source == target with LedgerError / HTTP 400.
LowAmounts are silently quantized to 0.01_parse uses quantize(Decimal("0.01")) with the default ROUND_HALF_EVEN. A local check showed 1.005 becomes 1.00 and 1.015 becomes 1.02. Extra precision is not rejected.Reject amounts that are not already two decimal places, or document the rounding and return the booked amount clearly.
LowNo IBAN format or checksum checkAny string can be used as an account key. Fine for a four-account demo; misleading if the API is reused.Validate IBAN structure, or clearly treat the values as opaque demo identifiers.
LowTest gaps, and a shared module-level ledger in the API testsThe 14 tests cover health, list accounts, a happy transfer, missing fields, unknown-account transfers, overdraft, and invalid amounts. They do not cover GET account/balance 404, list transfers, /readyz, the two extra routes, same-account transfers, or concurrency. API tests import the process-wide ledger, so they mutate one shared book.Reset the ledger per test. Add tests for the undocumented routes (without making outbound HTTP calls), GET 404s, and same-account transfers. A pytest.ini with pythonpath = . makes collection robust.
LowUnbounded in-memory journalEvery transfer is appended to a list in the worker and never trimmed. A noisy client can grow memory until the pod is evicted.Cap or persist the journal.

Recommended fixes

  1. Remove POST /api/v1/webhooks/verify, or put a strict allowlist in front of any outbound fetch. Do not let the app request arbitrary URLs from inside the cluster.
  2. Remove POST /api/v1/transfers/quick, or replace the cookie-as-IBAN pattern with a real authenticated session and a CSRF token.
  3. Do not leave POST /api/v1/transfers open on a public Route without authentication.
  4. Give the ledger a shared, transactional store, or run a single worker and a single replica while it stays in memory.
  5. Move the two trailing route definitions above if __name__ == "__main__".
  6. Pin the UBI base image and the app image to a digest or a dated tag, not :latest.
  7. Upgrade requests to 2.32.4 or later, and Flask to 3.1.3 or later. Optionally move gunicorn forward from 22.0.0 to a current pinned release.
  8. Reject same-account transfers, and reject (or clearly round and return) amounts with more than two decimal places.
  9. Reset the ledger per API test, add coverage for the extra routes without making outbound HTTP calls, and add a pytest.ini with pythonpath = ..
  10. Document every route in the README, or delete the routes the README does not mention.

SSRF callback (app.py)

@app.post("/api/v1/webhooks/verify")
def verify_webhook():
    """Confirm a customer-supplied callback URL is reachable."""
    payload = request.get_json(silent=True) or {}
    url = payload.get("callbackUrl", "")
    if not url:
        return jsonify(error="missing_fields", fields=["callbackUrl"]), 400

    response = requests.get(url, timeout=5)
    return jsonify(status="reachable", code=response.status_code)

Ledger transfer and overdraft floor (ledger.py)

def transfer(self, source, target, amount, reference=""):
    debit = self.get(source)
    credit = self.get(target)
    value = self._parse(amount)
    if debit.currency != credit.currency:
        raise LedgerError("cross-currency transfers are not supported")
    floor = -debit.overdraft_limit
    if debit.balance - value < floor:
        raise InsufficientFunds(source)
    debit.balance -= value
    credit.balance += value
