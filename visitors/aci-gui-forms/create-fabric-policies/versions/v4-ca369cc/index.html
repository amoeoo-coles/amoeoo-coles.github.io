Create Fabric Policies

NTP, BGP route reflectors and the pod policy group that applies them to a pod.

GUI: Fabric›Fabric PoliciesClass
datetimePolbgpInstPolfabricPodPGrp

This recipe covers the usual fabric-policy set: a Date and Time (NTP) policy, the BGP route-reflector nodes, and the Pod Policy Group that binds those policies onto a pod. There is no single “Create Fabric Policies” dialog in the APIC — the work is a short chain of forms under Fabric > Fabric Policies.

Then open Create Pod Policy Group and select the date-time and BGP RR policies (along with ISIS, COOP, management access and SNMP). Apply the group with the default pod profile at uni/fabric/podprof-default.

Recipe steps

  1. Create or edit a Date and Time policy and add NTP providers if the fabric should sync to external time.
  2. Add BGP route-reflector nodes (typically spines) under the default BGP RR policy.
  3. Create a Pod Policy Group that refers to those policies — see the existing Create Pod Policy Group page.
  4. Associate the group with a pod profile / pod selector so every pod uses it.

NaC YAML

Keys follow the local Cisco NaC fabric-policy modules (date/time, BGP RR, pod policy group).

YAML
apic:
  fabric_policies:
    # Date and Time policy (datetimePol) at uni/fabric/time-default
    date_time_policies:
      - name: default
        admin_state: true
        # ntp_servers: none were present in the AOAPIC snapshot
    # BGP route reflector (bgpInstPol / bgpRRP / bgpRRNodePEp)
    bgp_route_reflector:
      # pod 1, node 103 is the RR in the AOAPIC snapshot
      nodes:
        - 103
    pod_policy_groups:
      - name: default
        date_time_policy: default
        # also typically: isis_policy, coop_policy, bgp_rr_policy,
        # management_access_policy, snmp_policy
    pod_profiles:
      - name: default
        pod_selector:
          from: 1
          to: 1
        policy_group: default
