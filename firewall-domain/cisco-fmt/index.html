Cisco Secure Firewall Migration Tool

Cisco’s documented name for this product is the Secure Firewall Migration Tool (FMT). Aung’s phrase “Cisco firewall Migration Manager” maps to this tool. It parses a source firewall configuration and migrates it to Cisco Secure Firewall Threat Defense, managed by on-premises Firewall Management Center or by cloud-delivered FMC on Security Cloud Control. Source: Cisco Secure Firewall Migration Tool Release Notes, 10.0.3 Source: Migrating Cisco Secure Firewall ASA to Threat Defense with the Migration Tool: Getting Started

The tool itself is free. Destination-platform licences (FMC, threat defense and related subscriptions) are still required. The getting started guide says to obtain and apply valid Smart Licences on both the management center and threat defense before you migrate. Source: Migrating Cisco Secure Firewall ASA to Threat Defense with the Migration Tool: Getting Started

What it migrates

The 10.0.3 release notes (first published 13 May 2026) say the tool supports migration from Secure Firewall ASA, ASA with FirePOWER Services, FDM-managed devices, Microsoft Azure Native Firewall, and Check Point, Palo Alto and Fortinet firewalls, to Secure Firewall Threat Defense managed by management center or by cloud-delivered Firewall Management Center.Source: Cisco Secure Firewall Migration Tool Release Notes, 10.0.3

High-level workflow

The ASA workflow guide describes an end-to-end path that the other source-family guides follow with source-specific extraction steps.Source: Migrating Cisco Secure Firewall ASA to Threat Defense with the Migration Tool: Workflow

  1. Download and run the tool — Desktop installers for Windows and macOS, or the cloud version hosted on Security Cloud Control. Source: Cisco Secure Firewall Migration Tool Release Notes, 10.0.3 Source: Migrating Cisco Secure Firewall ASA to Threat Defense with the Migration Tool: Getting Started
  2. Extract or export the source configuration — From the CLI or ASDM, or by connecting the tool live to an ASA. Do not hand-edit the exported file.Source: Migrating Cisco Secure Firewall ASA to Threat Defense with the Migration Tool: Workflow
  3. Select the context and the destination — Multi-context ASA configs can be merged into a single instance. Then pick on-premises FMC or a Security Cloud Control region plus API token. Source: Migrating Cisco Secure Firewall ASA to Threat Defense with the Migration Tool: Getting Started Source: Migrating Cisco Secure Firewall ASA to Threat Defense with the Migration Tool: Workflow
  4. Review the pre-migration report — The tool parses the configuration and reports what it can and cannot migrate.Source: Migrating Cisco Secure Firewall ASA to Threat Defense with the Migration Tool: Workflow
  5. Map interfaces, security zones, interface groups and VRFs — Source interfaces must map to threat defense interfaces. Zones or interface groups are required for ACLs that use them.Source: Migrating Cisco Secure Firewall ASA to Threat Defense with the Migration Tool: Workflow
  6. Optimise, review and validate — Redundant, shadowed and disabled ACLs can be bulk-excluded. Object names and values are checked for conflicts.Source: Migrating Cisco Secure Firewall ASA to Threat Defense with the Migration Tool: Workflow
  7. Push to the management center — The tool pushes configuration; it does not deploy it. Demo mode cannot push.Source: Migrating Cisco Secure Firewall ASA to Threat Defense with the Migration Tool: Workflow
  8. Read the post-migration report and deploy from FMC — Then validate traffic on the threat defense.Source: Migrating Cisco Secure Firewall ASA to Threat Defense with the Migration Tool: Workflow
