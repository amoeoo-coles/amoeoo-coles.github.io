Review of the source diagram

The source diagram had two parts. The top was the ACI tenant object model. The bottom was a two-tenant sketch under root/uni.

On the object model, Tenant is the parent of application profile (AP), bridge domain (BD), VRF, L3Out, contract and filter (1:n). AP is the parent of EPG. Contract is the parent of subject. BD is the parent of subnet (1:n). Dashed relationships are EPG to BD (n:1), BD to VRF (n:1), L3Out to VRF (n:1), EPG to contract, and subject to filter. Solid lines are parent/child; dashed lines are relationships.

On the two-tenant sketch, Tenant A and Tenant B both used uni/tn-common/ctx-default. Tenant A had local BD1 with Subnet A and local EPG1/EPG2, and EPG3/EPG4 on uni/tn-common/BD-default (Subnet B, Subnet C). Tenant B had EPG1/EPG2 on that common BD-default, and local BD2 with Subnet D and EPG3/EPG4.

That model is correct. Two points are easy to miss:

  • EPGs that sit in different tenants on the shared BD still need contracts. Sharing a BD, and sharing the same VRF, does not replace the contract. By default the fabric still requires a contract between EPGs for data-plane traffic.
  • Subnets on uni/tn-common/BD-default, and the gateway addresses on those subnets, are owned by tenant common. They are children of the common BD. User tenants can place EPGs on that BD; they do not own the subnet object.

Five-tenant shared topology

The next drawing keeps that style and extends the bottom sketch from two tenants to five. Tenant1 to Tenant5 all sit under root/uni and all use uni/tn-common/ctx-default.

Each user tenant has a local BD (BD1 to BD5) with an example subnet (10.1.x.0/24, labelled example) and two local EPGs (EPG1, EPG2). Each tenant also has two EPGs (EPG3, EPG4) on the shared uni/tn-common/BD-default, which holds example Subnet B (10.0.2.0/24) and Subnet C (10.0.3.0/24). A shared L3Out in tenant common is associated with ctx-default.

Unlike the two-tenant source sketch, which swapped which EPGs were local in Tenant B, this five-tenant drawing is regular: every tenant has the same local-plus-shared layout. The prefixes are examples only; they were not taken from a live APIC.

Object hierarchy

Example distinguished names for this topology (names match the playbook):

  • uni — root
  • uni/tn-common — tenant common
  • uni/tn-common/ctx-default — shared VRF
  • uni/tn-common/BD-default — shared BD
  • uni/tn-common/BD-default/subnet-[10.0.2.1/24] — example Subnet B (gateway owned by common)
  • uni/tn-common/BD-default/subnet-[10.0.3.1/24] — example Subnet C (gateway owned by common)
  • uni/tn-common/out-Shared-L3Out — shared L3Out on ctx-default
  • uni/tn-common/brc-Shared-BD-Ct — example contract in common, used because shared-BD EPGs still need contracts
  • uni/tn-Tenant1 … uni/tn-Tenant5 — user tenants
  • uni/tn-Tenant1/BD-BD1 — local BD, associated with ctx-default, example subnet 10.1.1.1/24 (and BD2…BD5 in the other tenants)
  • uni/tn-Tenant1/ap-AP1/epg-EPG1 and epg-EPG2 — local EPGs on that tenant’s BD
  • uni/tn-Tenant1/ap-AP1/epg-EPG3 and epg-EPG4 — EPGs in the user tenant, associated with uni/tn-common/BD-default

Ansible playbook

Lab only. Do not run this playbook against a production APIC. Credentials are placeholders: {{ apic_host }}, {{ apic_username }} and {{ apic_password }}. The example vars file uses apic.example.invalid and CHANGE_ME. The shared L3Out task expects an external routed domain named Example-L3Dom to exist first. A contract in tenant common, with one example provide/consume pair on shared-BD EPGs (Tenant1 EPG3 and Tenant2 EPG3), is included because those EPGs still need contracts. This playbook was syntax-checked only; it was not run against an APIC.
