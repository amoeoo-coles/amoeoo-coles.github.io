Add the management port group to the lab VMs

No APIC screenshots are available for this page. The steps below are taken from the public Cisco Live ACI lab guide (LTRDCN-2143, pod1). Lab passwords are masked as •••••••• and are not republished. Where the lab page shows a screenshot (vSphere inventory or a VM console), that image is not copied here.

This section attaches the appropriate management EPG to the virtual machines so they can obtain a management IP address. To keep the lab simple, the DHCP server is already configured and operating for this pod. The VMs use Network Adapter 1 (eth0) for that management connection. The lab creates four VMs for the exercise:

  • POD01-WEB-SRV-01
  • POD01-WEB-SRV-02
  • POD01-APP-SRV
  • POD01-DB-SRV

It follows the Management Application Profile (aci_p01_ap_mgmt / EPG aci_p01_epg_mgmt) and the Mgmt Bridge Domain already documented on this site. The management EPG was associated with VMM domain aci_p01_dc3_vds, which is what presents the port group in vSphere. Context comes from PortGroup Add MGMT PortGroup to VM. Field values that do not appear on that lab page are not invented here.

Step 1 — Set the management port group on Network Adapter 1

Open the terminal to the lab Ansible host cl-srv1. The lab lists Username pod1u1 and Password •••••••• (the password from the lab page is not republished). Log in and run the playbook below. The -t eth0,power_on tags set the port group on Network Adapter 1 and power the VMs on.

cd cl-vm

ansible-playbook -i inventories/cl-vm/cl-vm.yml cl-vm.yml -t eth0,power_on

The lab page shows this task list and recap. The recap uses hostnames POD1-…, which differ from the POD01-… names in the introduction; both are shown as printed.

PLAY [pod1] ***********************************************************************************
The following task would be run:
    1. [cl-vm/set_portgroup : get VM info] 
    2. [cl-vm/set_portgroup : Set port group for Network Adapter 1]
    3. [cl-vm/power : Gather VM Runtime State]
    4. [cl-vm/power : Set VM Properties] 
    5. [cl-vm/power : Power On VM]

PLAY RECAP ******************************************************
POD1-APP-SRV              : ok=5    changed=2    unreachable=0     
POD1-DB-SRV               : ok=5    changed=2    unreachable=0     
POD1-WEB-SRV-01           : ok=5    changed=2    unreachable=0     
POD1-WEB-SRV-02           : ok=5    changed=2    unreachable=0

Step 2 — Connect to VMware vSphere

The lab says you should still have the vSphere Client browser window open. If not, open it with Username pod1u1 and Password •••••••• (again, the lab password is not republished). After login, the lab describes a screen that includes your datacenter, hosts, and the four VMs used in this section. That screenshot is on the lab page only and is not reproduced here. The lab does not name the datacenter or hosts in the text, so those labels are not invented here.

Step 3 — Console to POD01-WEB-SRV-01

Navigate to POD01-WEB-SRV-01, click the VM, then click Launch Web Console. The lab page includes a screenshot of this console that is not reproduced here.

Step 4 — Console to POD01-WEB-SRV-02

Navigate to POD01-WEB-SRV-02, click the VM, then click Launch Web Console.

Step 5 — Console to POD01-APP-SRV

Navigate to POD01-APP-SRV, right-click the VM, then click Launch Web Console.

Step 6 — Console to POD01-DB-SRV

Navigate to POD01-DB-SRV, right-click the VM, then click Launch Web Console.

Step 7 — Finish the hosts network configuration

The lab says it is important for the hosts to finish booting before continuing. On the browser tab with the session to pod1u1@cl-srv1, run the playbook with the host_cfg tag:

ansible-playbook -i inventories/cl-vm/cl-vm.yml cl-vm.yml -t host_cfg

The lab page shows this task list and recap. POD1-WEB-SRV-01 is the only host with seven ok/changed tasks and no skipped tasks; the other three show six ok/changed and one skipped.

PLAY [pod1] ***********************************************************************************
The following task would be run:
    1. [cl-vm/set_hostname : Set hostname] 
    2. [cl-vm/set_hostname : Update /etc/hosts file] 
    3. [cl-vm/set_hostname : Set hostname FQDN]
    4. [cl-vm/set_network : Configure network interfaces]
    5. [cl-vm/set_network : Restart networking service]
    6. [cl-vm/set_routes : Add IP route] 
    7 [cl-vm/set_routes : Update Route Table On WEB-SRV]

POD1-DB-SRV               : ok=6    changed=6    unreachable=0    failed=0    skipped=1    
POD1-WEB-SRV-01           : ok=7    changed=7    unreachable=0    failed=0    skipped=0

The Ansible recap hostnames (POD1-WEB-SRV-01, POD1-WEB-SRV-02, POD1-APP-SRV, POD1-DB-SRV) are shown exactly as on the lab page. They differ in spelling from the POD01-… names used in the introduction and console steps.
