1. HostHostAOAPIC: 11 static paths · NetBox: 0 device(s)

Provisioning steps and objects

  1. Create or pick the tenant, VRF, BD (with subnet/gateway) and application profile/EPG in NetBox (ACI plugin) as the source of truth.
  2. Access policies: VLAN pool with the host VLAN, physical domain, AAEP, and an access-port interface policy group (link level, CDP/LLDP).
  3. Interface profile + port selector on the leaf the host is cabled to; leaf profile ties it to the switch.
  4. Bind the EPG to the domain, then add a static path (leaf/port) with VLAN encapsulation (vlan-X, regular/trunk or access-untagged).
  5. Generate the NaC YAML from NetBox, dry-run, pre-check, apply through the aci-nac pipeline with approval, post-check.
  6. Verify: endpoint learned in the EPG (fvCEp) with the expected MAC/IP and encapsulation.

2. ServerServerAOAPIC: 64 vPC/PC policy groups · NetBox: 0 device(s)

Provisioning steps and objects

  1. Model the server and its uplinks in NetBox (device, interfaces, LAG) and the tenant/EPG it serves.
  2. Access policies: VLAN pool, physical domain, AAEP linking the domain to the interfaces.
  3. vPC (leaf pair) or port-channel (single leaf) interface policy group with LACP policy, link level and CDP/LLDP, pointing to the AAEP.
  4. Interface profile + port selectors on both vPC leaves (same ports), leaf profiles for the vPC pair.
  5. EPG domain binding and static path to the vPC/PC path (topology/pod-1/protpaths-101-102/pathep-[PG]) with VLAN encapsulation.
  6. Pipeline dry-run, pre-check, approved apply, post-check; verify vPC/port-channel up and endpoints learned on both leaves.

3. FirewallFirewallAOAPIC: 0 FW devices · NetBox: 0 device(s)

Provisioning steps and objects

  1. Model the firewall (role Firewall) and its interfaces in NetBox; decide routed (L3Out) or service-graph/PBR insertion.
  2. Access policies for the firewall ports (VLAN pool, physical domain, AAEP, vPC/PC or access policy group).
  3. L4-L7 device (vnsLDevVip, service type FW, physical or virtual) with concrete device and cluster interfaces (consumer/provider).
  4. Service graph template + device selection policy, or PBR (vnsSvcRedirectPol) with redirect destinations (IP/MAC) in a service BD.
  5. Attach the graph to the contract subject between consumer and provider EPGs; or build an L3Out to the firewall (routed design) or BD/EPG for transparent mode.
  6. Approved apply via the pipeline; verify graph instance deployed (vnsGraphInst), no L4-L7 faults, traffic redirected/permitted.

4. LoadBalancerLoadBalancerAOAPIC: 0 ADC devices · NetBox: 0 device(s)

Provisioning steps and objects

  1. Model the load balancer (role LoadBalancer) and its VIP subnets in NetBox.
  2. Access policies for the LB ports (VLAN pool, physical domain, AAEP, interface policy group).
  3. L4-L7 device (vnsLDevVip, service type ADC, one-arm or two-arm) with cluster interfaces.
  4. Service graph template (ADC function node) + device selection policy, attached to the contract for the VIP.
  5. VIP subnet on the BD (or EPG subnet), and SNAT/back-end subnets as designed; optional PBR for one-arm return traffic.
  6. Approved apply via the pipeline; verify graph instance deployed, VIP reachable and endpoints learned.

5. SpineSpineAOAPIC: 1 spine node(s) · NetBox: 3 device(s)

Provisioning steps and objects

  1. Rack, cable to all leaves, record the device (role Spine, serial, site/rack) in NetBox.
  2. Node registration on the APIC: fabric membership (fabricNodeIdentP) with serial, node ID, name and pod.
  3. Pod: confirm pod ID and TEP pool; spine joins via LLDP/IS-IS discovery from the leaves.
  4. BGP route reflector: add the spine to the fabric BGP RR policy (bgpRRNodePEp) and the pod policy group; set the fabric BGP ASN.
  5. Out-of-band/in-band management addresses and firmware group/maintenance group membership.
  6. Verify: node active in fabricNode, health, IS-IS/COOP/BGP up, no new faults.

6. LeafLeafAOAPIC: 2 leaf node(s) · NetBox: 6 device(s)

Provisioning steps and objects

  1. Rack, cable to every spine, record the device (role Leaf, serial, site/rack) in NetBox.
  2. Node registration on the APIC (fabricNodeIdentP): serial, node ID, name, pod.
  3. vPC pair: explicit vPC protection group (fabricExplicitGEp) with the two leaf node IDs and a vPC domain policy.
  4. Leaf profile (infraNodeP) with node selectors, linked to interface profiles (infraAccPortP) and port selectors (infraHPortS).
  5. Management addresses, firmware and maintenance groups.
  6. Verify: node active, health, vPC peer up, interface profiles applied, no new faults.
