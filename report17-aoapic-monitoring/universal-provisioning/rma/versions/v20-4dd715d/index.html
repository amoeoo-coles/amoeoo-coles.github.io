1. HostHostAOAPIC: 7 static paths · NetBox: 0 device(s)

RMA replacement steps

  1. Record the RMA in NetBox (old device/serial, case number) and the leaf ports the host uses.
  2. Re-cable the replacement to the same leaf ports (or update the port selector/static path if ports change).
  3. Re-bind: confirm the static path and VLAN encapsulation on the EPG still match; update NetBox interfaces/MAC if the NIC changed.
  4. Verify: port up, endpoint re-learned in the EPG with the new MAC, no faults on the path.

5. SpineSpineAOAPIC: 1 spine node(s) · NetBox: 1 device(s)

RMA replacement steps

  1. Decommission: confirm redundancy (other spines carry traffic), then decommission the node on the APIC (Fabric Membership → Decommission).
  2. Remove from controller: remove the node from the controller (decommission "remove from controller") so its registration is cleared.
  3. Register the new serial: power on the replacement, discover it, register with the same node ID, name and pod (fabricNodeIdentP), same firmware.
  4. Update NetBox: device serial (and asset/RMA notes).
  5. Verify: node active, BGP RR/IS-IS/COOP up, health restored, no new faults; compare config backup before/after.

6. LeafLeafAOAPIC: 2 leaf node(s) · NetBox: 2 device(s)

RMA replacement steps

  1. Decommission: move/confirm vPC peer carries traffic, then decommission the leaf on the APIC.
  2. Remove from controller so the old serial is cleared from fabric membership.
  3. Register the new serial with the same node ID, name and pod; same firmware; vPC protection group and leaf/interface profiles re-apply automatically by node ID.
  4. Re-cable host/server ports exactly as before; update NetBox serial.
  5. Verify: node active, vPC peer up, interfaces/static paths up, endpoints re-learned, no new faults.
