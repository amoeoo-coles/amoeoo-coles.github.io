ACI Multi-Site Terraform, Nexus ISN & Nexus Dashboard Orchestrator

v1 · 26 Nov 2026, 3:51 PM AEDT

Browser-only Cisco ACI Multi-Site workbench with 33 interactive forms that live-generate Terraform HCL for the CiscoDevNet/aci, CiscoDevNet/mso (Nexus Dashboard Orchestrator, platform = "nd") and CiscoDevNet/nxos providers, plus ready-to-paste NX-OS CLI. Includes original overview, physical and logical diagrams, an indicative BOM, rack elevations, a cabling plan, Day 1 / Day 2 / BAU / troubleshooting forms, a YAML sample model, Before-Push terraform plan previews, and a CI/CD + NetBox 4.x sync pack.

Offline & credential-safe by design: Everything renders locally in your browser; this page never contacts an APIC, Nexus Dashboard, or ISN switch. Generated .tf files always use variables (var.apic_password, var.ndo_password, var.nxos_password, var.apic2_password) or CI placeholders ({{ apic_password }}, {{ ndo_password }}) and documentation/lab prefixes. The plan panel is a browser preview (+ to add, ~ to change). A real terraform fmt / validate / plan / apply runs only on a self-hosted runner.
YAML data model: published at data/sample.yml and consumed in Terraform with yamldecode(file("${path.module}/data/sample.yml")).
Forms start with built-in defaults (same values as the sample file).

3.3 Step-by-Step Cabling, Labelling, Power and Airflow

  1. Print two labels per cable before seating optics, using the scheme in the table (device-port at both ends).
  2. Seat spine–ISN 100G LR4 links first (rows 1–8). Confirm light on both ends before moving on. These are the only inter-site data links in this design.
  3. Cable in-hall leaf–spine 100G SR4 MPO trunks, then vPC peer links and keepalive, then access ports, independently at each site.
  4. Cable OOB last, onto a management VRF/switch that does not transit VLAN-4. Documentation prefix 203.0.113.0/24 is an example only.
  5. Power: land A and B feeds on separate PDUs. Circuit amperage, breaker size and UPS runtime are not collected.
  6. Airflow: this sketch assumes port-side intake / front-to-rear exhaust. Confirm each PID’s airflow SKU before ordering; reversed-airflow units are not collected.
  7. Leave slack loops, strain-relieve MPO/LC, and photograph each rack after labelling for the as-built pack (not published here).
  8. Do not trunk server VLANs onto the ISN switches. The ISN carries the OSPF underlay (and whatever EVPN the design places on it); it is not a server leaf.

4. Planning & Prerequisites

Lock per-site TEP pools, ISN addressing and jumbo MTU before onboarding sites to NDO. The inter-site RTT limit is version-specific and is marked not collected unless you have it from Cisco documentation for your release.

Planning tree

Step-by-step planning guide

  1. Choose non-overlapping TEP pools and a unique external routable prefix for each site. Do not reuse a Multi-Pod TEP in a second site.
  2. Assign VLAN-4 /30s between every site spine and each ISN switch, plus a distinct fabric / BGP ASN per site.
  3. Confirm the ISN can carry jumbo frames end-to-end (example 9216 / 9150). Do not invent an RTT budget — look up the limit for your ACI and NDO versions.
  4. Load the sample model or type values, then copy the generated .tf into the automation repo.

5. Design Patterns (Terraform per Pattern)

Each pattern has its own Terraform module/config. Multi-Site objects usually live in NDO templates; a Multi-Pod fabric that joins Multi-Site is still one NDO site.

Design patterns

Step-by-step design guide

  1. Start with a stretched tenant and schema associated to both sites.
  2. Decide whether each VRF or BD stretches, and whether inter-site BUM is allowed (forms 5.3 vs 5.4).
  3. Keep site-local VRFs, L3Outs and domain bindings in a template associated to only one site.
  4. If one of the fabrics is Multi-Pod, onboard it as a single NDO site — never one site per pod.

6. Nexus ISN Switch Configs (NX-OS CLI & CiscoDevNet/nxos)

Bring the ISN underlay up before onboarding inter-site infra in NDO. Each form emits Terraform and paste-ready NX-OS. EVPN usually terminates on the site spines; apply the BGP form only to the Nexus that actually originates the session.

ISN bring-up

Step-by-step ISN bring-up

  1. Enable features and jumbo MTU, create VRF ACI-ISN and Loopback0.
  2. Build VLAN-4 subinterfaces toward every site spine, then OSPF in that VRF.
  3. Confirm OSPF FULL and end-to-end MTU with the verify form before NDO inter-site infra.
  4. Configure EVPN only on the device that terminates the session (often the site spines, via NDO infra or the APIC, not necessarily the ISN).

7. Day 1 — ND/NDO Onboarding and Inter-Site Infra

Finish the Nexus Dashboard cluster out of band, enable Orchestrator, onboard each APIC cluster as its own NDO site, record inter-site infra values, and create the first schema.

Day 1 order

Step-by-step Day 1

  1. Complete ISN OSPF and MTU first, independently of NDO.
  2. Bring up the Nexus Dashboard cluster and enable Orchestrator (not performed by CiscoDevNet/mso).
  3. Apply mso_site for Site 1 with var.apic_url, then Site 2 with var.apic2_url.
  4. Configure inter-site infra in NDO using the planned /30s; confirm the Terraform resource name for your NDO release before apply.
  5. Create the first schema and associate the stretched template to both sites.

8. Day 2 — Tenant, VRF, BD, EPG, Contracts and NDO Deploy

Day 2 objects for Multi-Site are declared in NDO templates and deployed with mso_schema_template_deploy_ndo.

Day 2 objects

Step-by-step Day 2

  1. Associate the tenant to both sites, then declare the stretched VRF and BD in the template.
  2. Add an application profile, EPG and contract. Bind the EPG to a domain in a site-specific follow-up (domain DN is not collected unless you add it).
  3. Deploy the template to both sites. The provider deploy resource is not always idempotent — a plan/apply may redeploy.

10. Troubleshooting (Show, moquery, terraform state)

Read-only diagnostics for ISN OSPF, inter-site EVPN/COOP, NDO deploy history and Terraform state/import. These forms do not declare write resources.

Diagnostics

Step-by-step diagnostic order

  1. If sites cannot reach each other’s TEPs, check ISN OSPF and end-to-end MTU first.
  2. If underlay is up but endpoints do not learn across sites, check EVPN on the spines and NDO inter-site infra, then COOP.
  3. If one site is missing template objects, read the NDO deploy history for that site and compare with the APIC.
  4. If Terraform drifts from the GUI, use terraform plan and terraform import with the real DN or resource ID — do not invent import IDs.
