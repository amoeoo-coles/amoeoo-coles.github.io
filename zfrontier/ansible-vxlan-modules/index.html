Ansible VXLAN EVPN Catalogue

v2 · 26 Nov 2026, 8:48 PM AEDT

An Ansible catalogue for VXLAN EVPN fabrics with 129 items: every role (7) and every data-model section (42) of Cisco’s VXLAN-as-code collection cisco.nac_dc_vxlan 0.9.1, the VXLAN EVPN modules of cisco.nxos 14.0.0 (59), and every module of cisco.dcnm 3.13.1 (21). Each item has its own YAML model and a numbered sample playbook that reads it with vars_files. Every model starts with a references block giving the documentation URL, the collection and version, the module or role, and the schema path. The playbooks run in build order: fabric and global settings, underlay, overlay, VRFs, networks, interfaces, policies, then deploy and Day 2. Attribute names, types, defaults and examples come only from the published data-model schema tables and the collections’ own documentation. Where a value isn’t documented, the model shows null.

Credential-safe by design: This page is a static catalogue and never contacts a switch or Nexus Dashboard. The inventory uses only the placeholders {{ nxos_host }}, {{ nd_host }}, {{ ansible_user }} and {{ ansible_password }}. Secret-like model fields are {{ ..._placeholder }} values. Do not commit real passwords. A live run belongs on a self-hosted runner that can reach your switches or Nexus Dashboard.

Playbooks, models and inventory

All 129 models and playbooks are published as real files, along with a combined playbook and one combined sample data model.

  • Combined end-to-end playbook: site.yml (imports every playbook in build order)
  • Combined sample data model: sample/vxlan-model.yml (one iBGP VXLAN EVPN fabric, plus every module model)
  • Inventory example: inventory.yml with placeholders {{ nxos_host }} {{ ansible_user }} {{ ansible_password }}
  • Per-item models: models/<name>.yml (a references block first, then the model)
  • Per-item playbooks: playbooks/<NNN>_<name>.yml

How the three collections fit together:

  • cisco.nac_dc_vxlan: you describe the fabric in vxlan: YAML under host_vars/<fabric>/. The validate role checks it, and dtc.create, dtc.deploy and dtc.remove push it through Nexus Dashboard. Each data-model playbook here checks its section and can stage it into host_vars (-e stage_model=true), then run validate (--tags validate).
  • cisco.dcnm: modules that call Nexus Dashboard Fabric Controller directly. The collection roles use them underneath.
  • cisco.nxos: modules that configure switches directly over CLI, without a controller.

Syntax-check locally with the collections installed:

ansible-galaxy collection install cisco.nac_dc_vxlan:0.9.1 cisco.nxos:14.0.0 cisco.dcnm:3.13.1
ansible-playbook --syntax-check -i inventory.yml site.yml

Approval email templates 129

Every item on this page has a click-to-approve provisioning approval email in the ACI NaC Pipeline layout: status banner, six-stage pipeline, context box, Approve and Deny buttons (a reply to 179172@gmail.com with APPROVE or REJECT), an original topology and logical view, design values and a pre-test summary. They are templates built from the example values here. Nothing is sent or applied, and pre-test, health and fault results are marked not collected.
