Process Meraki Webhook and Bounce Switch Port PoEThis workflow automates Tier 1 remediation when Meraki APs or cameras go down. It is triggered by a webhook and requires the Meraki webhook request body as input. The body is parsed; if parsing fails, the workflow stops. It evaluates two alert types: Network-level alerts (“APs went down” or “cameras went down”) and Organization-level alerts (“Unreachable device” with network names ending in “- camera” or “- wireless”). If neither condition matches, the workflow exits. If matched, it identifies the connected switch via device serial, bounces the switch port PoE, and checks device status. If online, it reports success. If not, it retries after 10 minutes. If still offline, Tier 2 escalation is triggered and failure is reported. Prerequisites: set target to “Execute on this target” (Meraki Endpoint), create a Webhook automation rule, and map the webhook request body input.50not collected5Cisco Meraki - Webhooks
