Design check

Does this design hold up?

Each item below was checked against official sources on 13 Nov 2026 (Melbourne time). The math uses published parameter counts and published bit widths. Engines, checkpoints or file sizes that are not official are labelled not verified. This is not a measured run on the PC.

Pass = official facts support the design. Warn = the design can work with limits. Fail = official numbers contradict a claim as drawn. Not verified = no official figure found.

1. VRAM fit

Fail Lead model on the RTX 5090 32 GB — weights do not fit in VRAM

Qwen3.8-Flash-Next is a real, official open-weight model (released 26 Aug 2026). The official card lists a 125-billion-parameter main model with 6 billion activated per token, plus 51 billion n-gram embeddings and a 4 billion MTP module [1] [2] [3]. The 5090 has 32 GB of GDDR7 [4].

NVIDIA documents NVFP4 as 4.5 bits per value (a 4-bit E2M1 value plus an FP8 scale shared by 16 values, and a negligible per-tensor FP32 scale) [5]. Using only that published bit width and the official parameter counts:

main 125B × 4.5 bits ÷ 8 = 70.312 GB n-gram 51B × 4.5 bits ÷ 8 = 28.688 GB (only if those embeddings were also NVFP4 — official cards do not say that) MTP 4B × 4.5 bits ÷ 8 = 2.250 GB main weights alone already 70.31 GB > 32 GB

Official n-gram embeddings are "more amenable to offloading than Mixture-of-Experts" [1] [2], and the host may offload them, but that does not bring the 125B main weights under 32 GB.

NVIDIA has published two related checkpoints, neither of which is a 32 GB GeForce fit:

  • nvidia/Qwen3.8-Flash-Next-NVFP4 is mixed precision (routed experts NVFP4, attention and shared experts BF16, n-gram embeddings FP8). The sample serve command uses --tensor-parallel-size 8. Supported test hardware is NVIDIA Blackwell B200 and B300, preferred OS Linux [6].
  • nvidia/Qwen3.8-Flash-Next-FP4-Local "occupies approximately 96 GiB on disk" and "is best suited for local AI hardware". It was validated on a single NVIDIA RTX PRO 6000 Blackwell (with PLE / n-gram offload) and on NVIDIA DGX Spark, with vLLM, preferred OS Linux [7]. The RTX PRO 6000 is a workstation GPU with much more memory than a 32 GB GeForce; the card does not list the RTX 5090 as a validated host.

Not verified I did not find an official Qwen NVFP4 file size, and I did not find an official Qwen or NVIDIA figure for how many gigabytes of shared (always-resident) weights remain after MoE expert offload. Warn The drawn memory policy ("5090 may offload to RAM") is therefore the only way this role can run, and it depends on a third-party engine — see item 6.

Pass Reviewer model on the W6800 32 GB — weights fit at a moderate context

Qwen3-Coder-30B-A3B-Instruct is officially 30.5 billion parameters in total and 3.3 billion activated, with a native context of 262,144 tokens [8]. The official config.json has 48 layers, 4 KV heads and head_dim 128 [9]. The W6800 has 32 GB of GDDR6 [10].

I did not find an official Qwen GGUF for this model, so the weight size is estimated from the official 30.5B count and the llama.cpp Q4_K tensor type of 4.5 bits per weight [11]. Q4_K_M is a mixed "medium" file type that typically keeps some tensors at a higher bit width, so the real file will be a little larger than this lower bound. That community file size is not used as a source here.

weights (Q4_K lower bound) 30.5B × 4.5 bits ÷ 8 = 17.156 GB KV cache (FP16, standard GQA formula, official config): 2 × 48 layers × 4 KV heads × 128 × seq × 2 bytes 32,768 tokens: 3.22 GB (3.00 GiB) 262,144 tokens (native): 25.77 GB (24.00 GiB)

Pass 17.16 GB of weights plus 3.22 GB (3.00 GiB) of KV at 32,768 tokens leaves headroom in 32 GB, which matches the policy that this helper keeps the model and the KV cache in VRAM. Warn At the model's native 262,144-token context the KV cache alone is 25.77 GB (24.00 GiB), and weights plus KV would not fit in 32 GB. Cap context on this server, or the "KV stays in VRAM" policy fails. Compute buffers on top of weights and KV are not published, so leave a margin.

Pass Repository assistant on the RTX 5060 Ti 16 GB — official Q6_K file fits at 32K context

Qwen3-8B is officially 8.2 billion parameters, 36 layers, GQA with 32 query heads and 8 KV heads, and 32,768 tokens of native context (131,072 with YaRN) [12]. The official config.json has head_dim 128 [13]. Qwen publishes an official GGUF; Qwen3-8B-Q6_K.gguf is 6,725,899,040 bytes (6.726 GB) [14]. The 5060 Ti is sold in 16 GB and 8 GB GDDR7 cuts; the diagram uses the 16 GB card, which matches the official 16 GB / 8 GB option [15].

official Q6_K file: 6,725,899,040 bytes = 6.726 GB check: 8.2B × 6.5625 bits ÷ 8 = 6.727 GB (llama.cpp Q6_K type) [11] KV cache (FP16, official config): 2 × 36 × 8 × 128 × seq × 2 bytes 32,768 tokens: 4.83 GB (4.50 GiB) 131,072 tokens (YaRN): 19.33 GB (18.00 GiB)

Pass 6.726 GB of weights plus 4.83 GB (4.50 GiB) of KV at the native 32,768-token context fits in 16 GB with some room for buffers. Warn At the 131,072-token YaRN length the KV cache alone is 19.33 GB (18.00 GiB), and weights plus KV would not fit. Keep context at the native 32K (or shorter) if KV must stay in VRAM.

2. PCIe slots on the MSI X870E Tomahawk

Pass The three slot labels in the diagram match MSI's specification

For a Ryzen 7000 or 9000 processor, MSI's official specification lists three physical x16 slots [16] [17]:

Slot (as drawn)MSI officialSource of lanes
PCI_E1 · top · PCIe 5.0 x16PCI_E1: PCIe 5.0, up to x16, from the CPU (x16 on Ryzen 9000/7000)CPU
PCI_E2 · middle · PCIe 3.0 x1PCI_E2: PCIe 3.0, up to x1, from the chipsetX870E chipset
PCI_E3 · bottom · PCIe 4.0 x4PCI_E3: PCIe 4.0, up to x4, from the chipsetX870E chipset

The 7950X is a Ryzen 7000 part, so PCI_E1 runs at PCIe 5.0 x16 [18] [16]. MSI's lane-sharing table says these three slots do not share bandwidth with each other [17].

Warn The x4 and x1 slots slow model loading, not in-VRAM inference

Standard PCI Express 128b/130b payload rates are about 0.985 GB/s per lane at Gen 3, 1.969 GB/s at Gen 4 and 3.938 GB/s at Gen 5 [19]:

PCI_E1 PCIe 5.0 x16 ≈ 63.02 GB/s PCI_E3 PCIe 4.0 x4 ≈ 7.88 GB/s PCI_E2 PCIe 3.0 x1 ≈ 0.98 GB/s theoretical minimum load time (payload only, no overhead): official 6.726 GB Q6_K over PCI_E2 ≈ 6.8 s 17.16 GB Q4_K lower bound over PCI_E3 ≈ 2.2 s

Once a model and its KV cache live entirely in VRAM, token generation is not limited by the slot. That matches the helper memory policy. The warnings are: (1) cold start and context load on the 5060 Ti over a Gen 3 x1 slot will be clearly slower than on a x16 slot; (2) if the 5090 offloads experts to RAM, those weights move over PCI_E1 at 63 GB/s, which is the fast slot — good — but every offloaded expert hop still costs host memory bandwidth and some PCIe traffic; (3) the W6800 is a PCIe 4.0 x16 card [10] sitting in an x4 slot, so it trains at x4.

Warn The three cards alone already exceed the 5090's recommended system power

Official board power figures:

1,005 W for the GPUs alone is already above NVIDIA's 1,000 W system recommendation for a PC that only has the 5090. I do not know the PSU in this machine, so this is not a fail against a named unit — it is a warning that the wall of official numbers requires a very high-capacity ATX PSU, enough dedicated PCIe power cables, and a realistic look at case airflow. The Founders Edition 5090 also needs 304 × 137 × 61 mm plus an extra slot in front of the fans [20]; the W6800 is a full-height, dual-slot, 10.5-inch card [10]. Three large cards in one case is a tight thermal and mechanical fit.

4. Mixing CUDA and Vulkan on Windows 11

Warn Separate processes can use NVIDIA CUDA and AMD Vulkan, but this mix is not officially validated as a kit

The 5090 and the 5060 Ti are NVIDIA Blackwell cards; official drivers are Game Ready or Studio drivers on Windows 11 [4] [15]. The W6800 is an AMD RDNA 2 workstation card with official Windows 11 64-bit support and Vulkan 1.2 [10]. llama.cpp publishes both CUDA and Vulkan backends [21].

I did not find an NVIDIA or AMD document that blesses or forbids running one CUDA server and one Vulkan server on the same Windows 11 PC. The practical, conservative reading is: install both vendors' current Windows 11 drivers, run each model in its own process bound to one GPU, and do not mix CUDA and Vulkan inside a single process. Display ownership, Hardware-accelerated GPU scheduling and driver order can still surprise a three-vendor setup, so treat first boot as a test, not a given.

5. LangGraph as the local CPU orchestrator

Pass Checkpointing, shared state, parallel branches and a join are documented features

The diagram's claims match the official LangGraph Graph API docs [22] [23]:

  • Shared state. Nodes read and write a graph state; reducers can append rather than overwrite, which is how patches, findings and tests can be collected from several workers.
  • Checkpointing. A checkpointer saves a snapshot of graph state at each super-step, organised into threads. That enables resume after a failure, human-in-the-loop interrupts and time travel. Pending writes from successful sibling nodes are kept if another branch in the same super-step fails [22].
  • Parallel branches and join. Two or more edges from the same node run in one super-step. A later node runs after those branches finish. For unequal branch lengths, defer=True on the join node waits until pending tasks complete [23].
  • Loop back on failure. Conditional edges can route back to an earlier node (here, the 5090 repair path) or to the end [23].

LangGraph does not itself load models or pool GPU memory; it calls the three local API servers. That matches "GPU memory is not pooled" and "models stay loaded".

6. The Strata engine

Not verified Strata exists as a third-party project; it is not a Qwen or NVIDIA runtime

The diagram names "Strata / CUDA" as the 5090 engine. A public GitHub project, Niko1221/Strata, describes itself as a way to run Qwen3.8-Flash-Next on consumer hardware with a local OpenAI/Anthropic-compatible API [24]. That is not an official Qwen or NVIDIA product.

Qwen's official card recommends SGLang, vLLM, TokenSpeed or KTransformers [1]. NVIDIA's official NVFP4 checkpoints are documented for vLLM on datacentre Blackwell (B200/B300, tensor parallel 8) or, for the "FP4-Local" build, on RTX PRO 6000 Blackwell and DGX Spark [6] [7].

Strata's own performance claims are not repeated here. If this role is built, treat Strata (or any other RAM-offload engine, including officially mentioned KTransformers) as an experiment: measure tokens per second, VRAM, and RAM on this PC, and do not assume a 32 GB card matches NVIDIA's 96 GiB local checkpoint results.

7. System memory on the 7950X

Warn The board lists 256 GB; AMD's 7950X page still lists 128 GB

The diagram shows 192 GB of RAM. MSI lists a maximum of 256 GB (four DDR5 UDIMMs) on the MAG X870E TOMAHAWK WIFI [16]. AMD's Ryzen 9 7950X product page lists a maximum of 128 GB [18]. I did not find an AMD page that explicitly rates the 7950X at 192 GB. 192 GB is therefore a board-level claim, not an AMD-listed CPU maximum, and should be confirmed in this machine's BIOS and memory QVL.
