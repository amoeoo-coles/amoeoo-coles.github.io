Ansible Cisco FMC Module Catalogue

v1 · 26 Nov 2026, 9:05 PM AEDT

Every module in the cisco.fmcansible Ansible collection (1.1.1, 3 modules), plus every FMC REST operation that the collection documents for its fmc_configuration module, listed as items under it (928 operations, 931 items in all). fmc_configuration calls any operation by its operationId, so each operation gets its own YAML model (operation, path_params, query_params, data) and a numbered sample playbook, in build order: system information, users, devices, HA and clusters, objects, policies, assignments, deployment, then integrations, health and operations.

Credential-safe by design: This page is a static catalogue and never contacts a controller. Connection options use the placeholders {{ fmc_host }} {{ ansible_user }} {{ ansible_password }} {{ domain_uuid }} from inventory.yml, and every password, key, token or community value in a model is a {{ vault_… }} placeholder. Every module that can change state is tagged never in its playbook, so site.yml runs only read-only modules unless you ask for a tag.

Files, models and samples

All 931 items are published as real files, plus combined files and a single sample data model.

  • site.yml: combined playbook that imports every playbook in build order (state-changing plays are tagged never)
  • sample/fmc-model.yml: combined sample data model
  • inventory.yml and ansible.cfg: placeholders only
  • playbooks/filter_plugins/cat_model.py: null-stripping filter used by every playbook
  • models/<module>.yml: one model per item, each opening with a references block
  • playbooks/<NNNN>_<module>.yml: one numbered sample playbook per item

Syntax-check locally with the collection installed:

ansible-galaxy collection install cisco.fmcansible:1.1.1
ansible-playbook --syntax-check -i inventory.yml site.yml
# Read-only run (info modules only; every state-changing play is tagged never):
ansible-playbook -i inventory.yml site.yml

Page: Ansible Cisco FMC Module Catalogue · Version: v1 · 26 Nov 2026, 9:05 PM AEDT

Collection: cisco.fmcansible 1.1.1 (3 modules in plugins/modules/), the latest on Ansible Galaxy on 26 Nov 2026. Module options come from ansible-doc --json. The operation items come from the collection’s own operation reference (samples/docs/operations/ and samples/docs/groups/ in FMCAnsible v1.1.1): operationId, API path, path and query parameters, and the body example. At run time fmc_configuration loads the operation list from your FMC’s own API spec, so an older or newer FMC may offer a different set.

Folder links end with /. Credentials are placeholders only ({{ fmc_host }} {{ ansible_user }} {{ ansible_password }} {{ domain_uuid }}). Addresses are documentation ranges only (192.0.2.0/24, 198.51.100.0/24, 203.0.113.0/24); other example addresses copied from upstream docs were moved into those ranges. No live device or controller was contacted; device output is not collected.
