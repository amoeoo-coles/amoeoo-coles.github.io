Terraform MSO Resource and Data Source Catalogue

v1 · 26 Nov 2026, 20:52 AEDT

Every resource and every data source in the CiscoDevNet/mso Terraform provider (3.1.0: 92 resources and 90 data sources, 182 catalogue entries), taken from terraform providers schema -json and the provider docs at the same tag. Each entry has its own YAML data model in models/ and a numbered sample tf/NNN_*.tf that reads it with yamldecode(file(...)). Numbers follow chronological fabric build order across the whole tree: system and fabric, access policies, tenant networking, applications, L4–L7, Multi-Pod / Multi-Site / Cloud, monitoring, utilities. Each data source follows its resource. Attribute names are exactly the schema’s. Nothing here is invented.

Credential-safe by design: this page is a static catalogue and never contacts an MSO or Nexus Dashboard Orchestrator. The provider block reads var.mso_url, var.mso_username and var.mso_password; terraform.tfvars.example holds the placeholder {{ mso_password }}. Secret attributes in models are {{ placeholders }} only. Do not commit real passwords. A live terraform plan belongs on a self-hosted runner that can reach your orchestrator.

Models, tf files and combined config

All 182 models and sample files are published as real files, plus a combined configuration that validates every one of them.

  • Provider and versions: providers.tf (CiscoDevNet/mso pinned to 3.1.0)
  • Variables: variables.tf and terraform.tfvars.example
  • Combined config: main.tf (module ./tf: every sample in build order, for validation; do not apply as-is)
  • Combined sample data model: sample/mso-model.yml
  • Per-item models: models/<name>.yml (data sources are data_<name>.yml)
  • Per-item samples: tf/<NNN>_<name>.tf

Validate locally (no orchestrator needed):

terraform init -backend=false
terraform fmt -check -recursive
terraform validate

Grouping and value rules

  • Group = chronological MSO/NDO build order from the resource or data source name: platform and sites, tenants, schema and templates, VRF, bridge domains, ANP/EPG, contracts, L3Out, service graphs, tenant policy templates, fabric policy and resource templates, then deploy and utility. The provider docs at this tag do not set a subcategory on every page, so grouping is by documented type name, not a guessed subcategory.
  • Order inside a group = dependency depth (from documented examples or DN format, when present), then name.
  • Model values: attributes required by the schema (or set in the docs minimal example) take the literal from the docs Example Usage. References to another object become REPLACE_ME with the referenced type in a comment. Every other attribute is null (omit, provider default).
  • Computed-only attributes are listed in each model header as exported attributes, not as inputs.

Gaps and not collected

  • Class is not collected for 182 of 182 items and DN for 182: the provider docs for those (mostly older SDKv2 resources) do not state an API class or DN format.
  • No docs page at this tag, so placed in group 9 Other: .
  • Marked deprecated in the schema: data.mso_label, data.mso_remote_location, data.mso_role, data.mso_schema_site_anp_epg_selector, data.mso_schema_site_contract_service_graph_listener, data.mso_schema_site_external_epg_selector, data.mso_schema_site_vrf_region, data.mso_schema_site_vrf_region_cidr, data.mso_schema_site_vrf_region_cidr_subnet, data.mso_schema_site_vrf_route_leak, data.mso_schema_template_anp_epg_selector, data.mso_schema_template_contract_filter, data.mso_schema_template_external_epg_selector, data.mso_service_node_type, data.mso_system_config, data.mso_user, mso_label, mso_remote_location, mso_schema_site_anp_epg_selector, mso_schema_site_contract_service_graph_listener, mso_schema_site_external_epg_selector, mso_schema_site_service_graph_node, mso_schema_site_vrf_region, mso_schema_site_vrf_region_cidr, mso_schema_site_vrf_region_cidr_subnet, mso_schema_site_vrf_route_leak, mso_schema_template_anp_epg_selector, mso_schema_template_contract_filter, mso_schema_template_deploy, mso_schema_template_external_epg_selector, mso_service_node_type, mso_site, mso_system_config, mso_tenant, mso_user.
  • REPLACE_ME values (493 in total) are references to another object in the docs example (for example tenant_id = mso_tenant.example.id). Set them to that object’s DN, or swap the model value for a Terraform reference in your own module.
  • Two files carry a _file suffix (*_override_file.tf) because Terraform treats any file ending _override.tf as an override file.
  • Nothing was applied to an MSO or Nexus Dashboard Orchestrator. Validation is terraform validate only; live plan/apply needs a self-hosted runner that can reach the orchestrator.
