Ansible cisco.nxos Module Catalogue

v1 · 26 Nov 2026, 6:30 PM AEDT

Every module in the cisco.nxos Ansible collection (14.0.0, 80 modules), taken from the installed collection’s DOCUMENTATION and EXAMPLES. Each module has its own YAML data model and a sample playbook that reads that model with vars_files. Every model starts with a references block: the official doc URL, the source file at the release tag, collection and version, module type, documented states and where the sample values came from. Playbooks are numbered in chronological NX-OS build order: system and bootstrap, AAA and management, interfaces, Layer 2, Layer 3 routing, multicast, VXLAN EVPN, ACLs, QoS, monitoring, operations, then SAN / Fibre Channel. Keys are only the options the module documents; sample values come only from the module’s own EXAMPLES, otherwise null (omit). Nothing here is invented.

Credential-safe by design: This page is a static catalogue. It never contacts a switch. The inventory uses only the placeholders {{ nxos_host }}, {{ ansible_user }} and {{ ansible_password }}, and every password, key or SNMP community in a model is a {{ vault_… }} placeholder. Addresses come from the module documentation, with private 192.168.x.x examples moved to the 198.51.100.0/24 documentation range. Disruptive plays (reboot, install_os, rollback, GIR) are tagged never so site.yml skips them unless asked. A live run belongs on a self-hosted runner that can reach your switches.

Playbooks, models and inventory

All 80 models and playbooks are published as real files, plus a combined playbook and a single sample data model.

  • Combined end-to-end playbook: site.yml (imports every playbook in build order)
  • Combined sample data model: sample/nxos-model.yml
  • Null-stripping filter used by the playbooks: playbooks/filter_plugins/nxos_model.py and ansible.cfg
  • Inventory example: inventory.yml with placeholders {{ nxos_host }} {{ ansible_user }} {{ ansible_password }} (network_cli, with httpapi as a commented alternative)
  • Per-module models: models/<module>.yml
  • Per-module playbooks: playbooks/<NNN>_<module>.yml

Syntax-check locally with the collection installed:

ansible-galaxy collection install cisco.nxos:14.0.0
ansible-playbook --syntax-check -i inventory.yml site.yml
# Read-only Day 2 check (gathered state on every resource module):
ansible-playbook -i inventory.yml site.yml --tags gathered \
  -e nxos_host=nxos-01.example.net -e ansible_user=admin -e ansible_password='***'

Feature enablement first, then hostname, system/DNS settings, login banner and NTP. Cards load their YAML model and sample playbook when they scroll into view.

Local users, TACACS+/RADIUS server settings and hosts, and the NX-API management interface. Cards load their YAML model and sample playbook when they scroll into view.

3. Interfaces 5

Physical and logical interface attributes, LLDP and UDLD. Cards load their YAML model and sample playbook when they scroll into view.

4. Layer 2 (VLANs, VTP, LACP, vPC) 10

VLANs, VTP, access/trunk switchports, LACP, port-channels and vPC. cisco.nxos 14.0.0 has no dedicated spanning-tree module. Cards load their YAML model and sample playbook when they scroll into view.

5. Layer 3 routing 22

VRFs, L3 interfaces, static routes, prefix lists, route maps, OSPFv2/v3, BGP, BFD, HSRP and VRRP. Cards load their YAML model and sample playbook when they scroll into view.

6. Multicast 6

IGMP, IGMP snooping and PIM (global, interface and RP address). Cards load their YAML model and sample playbook when they scroll into view.

7. VXLAN EVPN 7

Anycast gateway MAC, EVPN control plane, NVE interface / VTEP, VNI membership and EVPN VNI settings. Cards load their YAML model and sample playbook when they scroll into view.

8. Security and ACLs 2

IPv4/IPv6 access lists and their interface bindings. Cards load their YAML model and sample playbook when they scroll into view.

9. QoS 0

cisco.nxos 14.0.0 ships no dedicated QoS module. Use cisco.nxos.nxos_config (group 11) for QoS policy CLI.

10. Monitoring, logging and SNMP 3

Syslog, SNMP server and model-driven telemetry. Cards load their YAML model and sample playbook when they scroll into view.

11. Operations and utility 12

Facts, show commands, raw config, file copy, NX-OS install, RPM, snapshots, rollback, maintenance mode (GIR), ping and reboot. Cards load their YAML model and sample playbook when they scroll into view.

12. SAN / Fibre Channel 4

VSANs, FC interfaces, device aliases and zones/zonesets. These modules state in their own documentation that they target Fibre Channel (MDS / Nexus FC) platforms. Cards load their YAML model and sample playbook when they scroll into view.

13. Other 0

Modules that do not fit the groups above. Nothing is guessed into another group. Empty in cisco.nxos 14.0.0.
