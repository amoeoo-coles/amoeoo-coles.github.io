📡 MWMESH

MWMESH is MountainWest Mesh, a community-run, off-grid LoRa messaging network. Its official site describes messaging across the Mountain West without cell towers or the internet, starting with a LoRa radio. The official title names Utah, Idaho and Wyoming; the same homepage also lists Las Vegas and the line “4 states connected”. It is labelled “100% community-run”. No company or named operator is stated on that homepage [1].

Facts on this page were read from official MWMESH and MeshCore pages on 13 Nov 2026 (Melbourne time). The coverage list is a rough cluster summary of a map supplied that day. The map image itself is not published here, and no node coordinates are given.

Firmware: MeshCore, not a guess

MountainWest Mesh tells new users to install MeshCore, then apply the regional community settings. The flash, setup and settings pages, and the node configurator, are all MeshCore-based [1] [2] [3] [4]. MeshCore is an MIT-licensed, off-grid, open-source encrypted messaging system that uses LoRa. The official MeshCore site says the app is made in New Zealand and the firmware is made in Australia. Official documentation starts at the MeshCore docs introduction [5] [6] [7].

Meshtastic is a different firmware. MWMESH’s own how-to pages instruct people to flash MeshCore. This page does not treat MWMESH as a Meshtastic network. A similar mesh in Australia may still choose Meshtastic; that is covered on the Australia plan.

How off-grid LoRa mesh messaging works

Each person needs a companion LoRa radio. The MeshCore app on a phone or computer talks to that radio over Bluetooth (or USB). The radio, not the phone, sends and receives LoRa packets. You do not need Wi-Fi or cellular service for the mesh itself [3] [5].

Companion radio

The usual personal firmware. It pairs with the app for messaging and optional location sharing. Official MeshCore FAQ: companion clients do not repeat, so ordinary user devices do not rebroadcast other people’s traffic [8] [9].

Repeater

A dedicated relay, often placed high, that forwards traffic without a phone attached. It does not automatically retransmit every packet it hears; it forwards packets that match its role and settings [8] [9].

Room server

Hosts group rooms, stores posts, and serves them later, more like a bulletin board than a live channel. Official FAQ: a room can also repeat if set repeat on is used, but that is not recommended; run a separate repeater [8] [9].

Observer / MQTT feeder

On MWMESH this is not a separate on-air role. It is a repeater or room server that also uplinks received packets over the internet for maps and monitoring [8].

The first direct message to a new contact is flood-routed through repeaters. The destination returns the path it used, and later messages can follow that learned direct path, so only the repeaters on the path retransmit. Group channels have no single destination path, so they always flood. Internally, MeshCore’s hop limit is 64 with 1-byte path hashes; 2-byte paths (MWMESH’s current community standard) support a maximum of 32 hops. Real-world paths are usually much shorter [9] [10] [11].

MWMESH also notes that delivery is best-effort: if the recipient is out of range or offline, the message may not arrive immediately. Repeaters and room servers improve the chance of getting through. Keep messages short; the mesh is a shared radio resource [8].

Encryption

MeshCore and MWMESH both describe messaging as encrypted by default. Direct messages are end-to-end encrypted: MWMESH says only the sender and recipient can read them, and that they stay between those two parties rather than a central platform [5] [1] [8].

Official MeshCore documentation is more specific:

  • Identity. Each node has an Ed25519 public key. Adverts can broadcast a name, optional position and that public key, signed so the identity is harder to spoof [12] [9] [13].
  • Key exchange. Official KISS-modem docs list X25519 (ECDH) for key exchange [13].
  • Direct messages (PKI). Encrypted text payloads carry destination and source hashes taken from those public keys, plus a MAC and ciphertext, so a private DM is keyed to the two identities [12].
  • Symmetric crypto. Official MeshCore docs specify AES-128 block encryption with zero padding, then HMAC-SHA256 truncated to 2 bytes (encrypt-then-MAC) [13].
  • Channels. Group messages are encrypted with a shared channel key (the channel is identified by a hash of that key). Official payload docs warn that group sender names are not signed, so anyone who holds the channel key can pick a display name [12] [5].

US frequency (the 915 MHz band)

MWMESH’s device page says every listed radio must be the US 915 MHz frequency variant [14]. That is the familiar name for the US ISM allocation. The community’s actual recommended centre frequency is not 915.000 MHz. MountainWest Mesh’s settings page states:

SettingMWMESH community value
Frequency910.525 MHz, described as the standard frequency for mwmesh.com within the US 902–928 MHz ISM band
Bandwidth62.5 kHz
Spreading factorSF7
Coding rateCR5 (4/5)
TX power (handheld recommendation)22 dBm; account for antenna gain and stay within 30 dBm EIRP
Path hash size2 bytes (32 hops maximum), on firmware 1.14 or newer

These are community interoperability recommendations. MWMESH says users remain responsible for FCC Part 15 compliance [11] [3]. Nodes only hear each other if the radio parameters match.

How to join MountainWest Mesh

The official site says no radio licence or networking background is required, and it offers this five-step path [1] [2] [3] [4]:

  1. Join the community and find local operators on mwmesh.com.
  2. Choose a radio that MeshCore supports, in the US 915 MHz variant [14] [15].
  3. Install MeshCore with the web flasher at flasher.meshcore.io in a Chromium-based browser (Chrome or Edge). Pick Companion, Repeater or Room Server firmware to match the role [2].
  4. Apply regional settings with the mwmesh Configurator, or enter the table above by hand, then set a short node name [4] [3].
  5. Say hello — discover nearby nodes, join a room, and send a message [1].

The official homepage lists these cities: Salt Lake City, Provo, Ogden, Logan, St. George, Las Vegas, Boise, Twin Falls, Pocatello, Idaho Falls, Rock Springs and Jackson Hole [1].
