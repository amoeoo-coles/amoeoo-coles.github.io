Terraform VXLAN EVPN Resource Catalogue

v1 · 26 Nov 2026, 5:58 PM AEDT

Every VXLAN EVPN resource in the CiscoDevNet/nxos Terraform provider (0.22.3) and every resource in the CiscoDevNet/ndfc provider (0.3.1), 47 resources in all. Each resource has its own YAML data model, with a references block (registry doc, provider and version, resource name) and a comment for every attribute, plus a numbered sample .tf that reads the model with yamldecode(file(...)). Files are numbered in build order: global settings and fabrics, underlay, VTEP and overlay, VRFs / L3VNI, networks / L2VNI, interfaces and access, then Day 2. Nothing here is invented: unknown values are null (not collected).

Credential-safe by design: This page is a static catalogue and never contacts a switch or Nexus Dashboard. providers.tf reads credentials only from variables (var.nxos_password, var.ndfc_password and so on). Models contain no passwords or keys. Put real values in terraform.tfvars or TF_VAR_* environment variables on your runner, and never commit them.

Terraform files and models

All 47 models and sample .tf files are published as real files, plus a combined configuration.

  • Combined configuration: providers.tf, variables.tf and main.tf (every resource in build order, each waiting for the previous one of the same provider)
  • Combined sample data model read by main.tf: sample/vxlan-model.yml
  • Variables example with placeholders: terraform.tfvars.example
  • Per-resource models: models/<resource>.yml
  • Per-resource samples: tf/<NNN>_<resource>.tf (copy providers.tf and variables.tf next to them)

Check locally (no device needed):

terraform fmt -check -recursive
terraform init -backend=false
terraform validate

Scope and sources

  • CiscoDevNet/nxos 0.22.3: 28 of its 61 resources, the ones used to build a VXLAN EVPN fabric (features, underlay, NVE, EVPN, VRFs, VLAN/VNI, SVIs, interfaces, vPC, Day 2 helpers).
  • CiscoDevNet/ndfc 0.3.1: all 19 of its 19 resources.
  • Resources only. Data sources are not included.
  • Attribute names, types, required flags and descriptions come from terraform providers schema -json. Sample values come from each provider’s own examples/resources/<name>/resource.tf at the release tag. Public addresses in those examples were mapped to documentation ranges, and passwords or keys were removed (set to null). Anything else is null (not collected), so the provider default applies.
  • Deprecated and write-only attributes are left out of the models. Write-only secrets should be set from variables when you need them.
  • nxos resources not in this catalogue (not VXLAN EVPN specific): nxos_access_list, nxos_analytics, nxos_default_qos, nxos_eigrp, nxos_epbr, nxos_esg, nxos_hardware_telemetry, nxos_hsrp, nxos_icmpv4, nxos_icmpv6, nxos_igmp, nxos_ipv6, nxos_keychain, nxos_logging, nxos_macsec, nxos_management_interface, nxos_netflow, nxos_network_qos, nxos_ntp, nxos_ospfv3, nxos_poe, nxos_ptp, nxos_queuing_qos, nxos_segment_routing, nxos_sla, nxos_snmp, nxos_span, nxos_telemetry, nxos_track, nxos_user_management, nxos_vrrp, nxos_vrrpv3, nxos_vtp.

1. Global, fabric and features 7

Fabric-wide and switch-wide settings that come first: NX-OS features, system and platform (NVE/TCAM) settings, and NDFC fabric creation plus switch inventory. Cards load their model and .tf when they scroll into view.

2. Underlay 8

Loopbacks, IPv4 addressing / static routes, IGP (OSPF or IS-IS), BFD and multicast underlay (PIM, MSDP anycast RP), plus NDFC fabric links. Cards load their model and .tf when they scroll into view.

3. VTEP and overlay 3

NVE interface (VTEP), BGP with the L2VPN EVPN address family, and global EVPN VNI route distinguisher / route target settings. Cards load their model and .tf when they scroll into view.

4. VRFs and L3VNI 3

Tenant VRFs with RD / route targets, route maps and prefix lists used for VRF redistribution, and NDFC VRFs. Cards load their model and .tf when they scroll into view.

5. Networks and L2VNI 6

VLAN-to-VNI bridge domains, anycast gateway (HMM), SVIs, IGMP snooping for VXLAN, DHCP relay, and NDFC networks. Cards load their model and .tf when they scroll into view.

6. Interfaces and access 11

Physical, vPC, port-channel and sub-interfaces, spanning-tree edge settings, NDFC vPC pairs and NDFC interface resources. Cards load their model and .tf when they scroll into view.

7. Day 2 and operations 7

Generic DME / CLI / REST escape hatches, NDFC templates and policies, configuration deploy and saving the running config. Cards load their model and .tf when they scroll into view.

8. Other 2

NDFC resources that are not VXLAN EVPN fabrics (IP Fabric for Media and LAN Classic fabric types). Included because every ndfc resource is in scope. Cards load their model and .tf when they scroll into view.
