ACI Multi-Pod Terragrunt, Nexus IPN & Nexus Dashboard

v2 · 26 Nov 2026, 8:48 PM AEDT

Browser-only Cisco ACI Multi-Pod workbench with 38 interactive forms that live-generate terragrunt.hcl and reusable Terraform module HCL for the CiscoDevNet/aci, CiscoDevNet/mso (Nexus Dashboard Orchestrator, platform = "nd") and CiscoDevNet/nxos providers, plus ready-to-paste NX-OS CLI. Includes original overview, physical and logical diagrams, an indicative BOM, rack elevations, a cabling plan, Day 1 / Day 2 / BAU / troubleshooting forms, a YAML sample model, Before-Push terraform plan previews, and a CI/CD + NetBox 4.x sync pack.

Offline & credential-safe by design: Everything renders locally in your browser; this page never contacts an APIC, Nexus Dashboard, or IPN switch. Generated terragrunt.hcl and module .tf files always use variables (var.apic_password, var.ndo_password, var.nxos_password) or CI placeholders ({{ apic_password }}, {{ ndo_password }}) and documentation/lab prefixes. The plan panel is a browser preview of terragrunt run --all plan (+ to add, ~ to change). A real terragrunt hcl format / run --all validate / run --all plan / apply runs only on a self-hosted runner.
YAML data model: published at data/sample.yml and consumed in Terragrunt units with yamldecode(file("${get_repo_root()}/data/sample.yml")).

3.3 Step-by-Step Cabling, Labelling, Power and Airflow

  1. Print two labels per cable before seating optics, using the scheme in the table (device-port at both ends).
  2. Seat spine–IPN 100G LR4 links first (rows 1–8). Confirm light on both ends before moving on. These are the only inter-hall data links in this design.
  3. Cable in-hall leaf–spine 100G SR4 MPO trunks, then vPC peer links and keepalive, then access ports.
  4. Cable OOB last, onto a management VRF/switch that does not transit VLAN-4. Documentation prefix 203.0.113.0/24 is an example only.
  5. Power: land A and B feeds on separate PDUs. Circuit amperage, breaker size and UPS runtime are not collected.
  6. Airflow: this sketch assumes port-side intake / front-to-rear exhaust. Confirm each PID’s airflow SKU before ordering; reversed-airflow units are not collected.
  7. Leave slack loops, strain-relieve MPO/LC, and photograph each rack after labelling for the as-built pack (not published here).
  8. Do not trunk server VLANs onto the IPN switches. IPN carries OSPF, PIM bidir and DHCP relay only.

4. Terragrunt live/ Repo Layout

Starter live/ tree for lab and prod, with reusable Terraform modules under modules/. Every unit includes the root terragrunt.hcl (remote state with locking, generated providers), reads _envcommon/, points at a module with terraform { source = "${get_repo_root()}/modules/<unit>" }, and takes inputs from the YAML model via yamldecode(file("${get_repo_root()}/data/sample.yml")). Copy this tree into a private automation repository before running terragrunt run --all (classic: run-all).

Terragrunt layout

Step-by-step layout

  1. Start from the published live/ tree and set root remote_state plus generate provider blocks. Credentials stay in environment variables.
  2. Fill live/lab/env.hcl and live/prod/env.hcl, and keep shared inputs in _envcommon/.
  3. Add one unit folder per environment and per site or pod role (infra, ipn, fabric, tenants) with terraform {{ source = ... }}.
  4. Wire dependency blocks with mock_outputs so validate and plan can run before apply.
  5. Plan and apply with terragrunt run --all in DAG order; use a scheduled plan with -detailed-exitcode for drift. The browser cannot see remote state.

5. Planning & Prerequisites

Lock TEP pools, IPN addressing and MTU/RTT before any device is provisioned. Forms emit Terraform that Day 1 will apply.

Planning tree

Step-by-step planning guide

  1. Choose non-overlapping TEP pools for each pod and a unique external routable /24 per pod.
  2. Assign VLAN-4 /30s between every spine and each IPN switch, plus a phantom RP address.
  3. Confirm the IPN can carry ≥ 9150 byte frames and that pod-to-pod RTT is ≤ 50 ms.
  4. Load the sample model or type values, then copy the generated .tf into the automation repo.

6. Design Patterns (Terragrunt + Terraform module per Pattern)

Each pattern has its own Terraform module/config. A Multi-Pod fabric is still one APIC cluster, so Nexus Dashboard Orchestrator inventories it as one site.

Design patterns

Step-by-step design guide

  1. Start with the dual-pod dual-IPN root module so later forms share fabric and site names.
  2. Decide whether BDs flood BUM (GIPo over PIM bidir) or use hardware-proxy / drop.
  3. Pick local-egress L3Outs or a shared L3Out; this page models the local-egress pattern.
  4. If NDO will own tenant policy, declare the schema and template before Day 2 deploys.

7. Nexus IPN Switch Configs (NX-OS CLI & CiscoDevNet/nxos)

Bring the IPN up before discovering Pod 2. Each form emits Terraform and paste-ready NX-OS.

IPN bring-up

Step-by-step IPN bring-up

  1. Enable features and jumbo MTU, create VRF ACI-IPN and Loopback0.
  2. Build VLAN-4 subinterfaces toward every spine, then OSPF in that VRF.
  3. Enable DHCP relay to the Pod 1 APIC infra TEPs before powering Pod 2 spines.
  4. Configure PIM bidir and the phantom RP so GIPo groups can cross the IPN.
  5. Run the verify form (OSPF FULL, MTU, PIM neighbors) before Day 1 fabric setup.

8. Day 1 — Fabric Bring-Up, Infra L3Out, ND/NDO Onboarding

Register the new pod, attach pod policies, build the infra Multi-Pod L3Out, assign external TEPs, and add the fabric to Nexus Dashboard Orchestrator as one site.

Day 1 order

Step-by-step Day 1

  1. Complete IPN OSPF and DHCP relay first.
  2. Push fabricSetupP for Pod 2 and the external routable subnet.
  3. Discover and register Pod 2 spines, then leaves.
  4. Bring up the infra L3Out so TEP pools are advertised across the IPN.
  5. Finish the Nexus Dashboard cluster out of band, enable Orchestrator, then apply mso_site.

9. Day 2 — Tenant, VRF, BD, EPG, Contracts and NDO Deploy

Day 2 objects are fabric-wide in Multi-Pod. Use the ACI provider directly, or declare them in an NDO template and deploy with mso_schema_template_deploy_ndo.

Day 2 objects

Step-by-step Day 2

  1. Create the tenant and VRF, then the stretched BD and subnet.
  2. Add an application profile, EPG and contract, and bind the EPG to a domain (domain DN is not collected unless you add it).
  3. If NDO owns the policy, deploy the template to the single Multi-Pod site.

11. Troubleshooting (Show, moquery, Terragrunt cache and state)

Read-only diagnostics for DHCP relay, MTU, OSPF, EVPN/COOP and Terraform state/import. These forms do not declare write resources.

Diagnostics

Step-by-step diagnostic order

  1. If a new spine has no TEP, check DHCP relay and reachability to Pod 1 APIC TEPs first.
  2. If OSPF stays in EXSTART, compare MTU on both ends of VLAN-4.
  3. If TEPs exist but endpoints do not learn across pods, check PIM bidir, GIPo and COOP/EVPN.
  4. If Terraform drifts from the GUI, use terraform plan and terraform import with the real DN — do not invent import IDs.
