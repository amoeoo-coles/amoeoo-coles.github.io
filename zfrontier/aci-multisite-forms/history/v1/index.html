ACI Multi-Site GUI Forms, Nexus Dashboard Orchestrator & ISN Generator

v1 · 26 Nov 2026, 3:21 PM AEDT

Browser-only Cisco ACI Multi-Site workbench with 35 interactive forms that live-generate cisco.mso, cisco.nd and cisco.nxos Ansible YAML playbooks plus ready-to-paste NX-OS ISN CLI and diagnostic commands as you type. Includes original interactive overview, physical and logical topology diagrams, an indicative BOM, rack elevations and a cabling plan, design-pattern playbooks, Day 1 / Day 2 Nexus Dashboard Orchestrator workflows, BAU and lifecycle management, a published YAML sample data file, Before-Push inspection panels, and a CI/CD + NetBox 4.x sync pack.

Offline & credential-safe by design: Everything renders locally in your browser; this page never contacts Nexus Dashboard, NDO, an APIC or an ISN switch. Generated playbooks always use vault/inventory placeholders ({{ ndo_host }}, {{ ndo_password }}, {{ nd_password }}, {{ apic_password }}, {{ nxos_username }}, {{ nxos_password }}) and example documentation/lab IP ranges (including RFC 5737 TEST-NET). Replace all example addressing before running in CI. The CI pack is not executed from this Pages repository and needs a self-hosted runner to reach a lab.

3.3 Step-by-Step Cabling and Labelling

  1. Confirm rack elevations, PDU feeds and aisle orientation against the hall drawing (drawing itself is not collected until you supply one).
  2. Label both ends of every cable before it goes in, using the scheme {site}-{rack}-{ru}-{device}-{port} (example: S1-R1-U40-SPINE101-E1/31).
  3. Land CIMC / OOB first and verify lights, so hardware is reachable if the fabric is down.
  4. Cable APIC VIC ports dual-homed to a leaf vPC pair. Do not place both APIC uplinks on the same leaf.
  5. Cable leaf–spine 100G SR4 uplinks per the port map. Keep vPC peers on both spines.
  6. Cable spine–ISN 100G LR4 (or SR4 if the ISN is in the same hall). Use VLAN-4 subinterfaces later; the physical port is a routed parent.
  7. Cable the ISN-1 to ISN-2 core link and the Site 2 spine–ISN links the same way.
  8. Cable Nexus Dashboard management and data ports. Leave cluster bootstrap until OOB and DNS/NTP are confirmed.
  9. Dress cables, fill residual slack in managers, and photograph each RU face for the as-built pack.
  10. Record serials, port maps and label IDs in NetBox (or your source of truth) before any production cutover. Fibre metres remain not collected until measured.

4. Planning & Prerequisites

Reserve overlay TEPs, BGP-EVPN router-IDs, ISN addressing and an MTU 9150+ path before any switch or NDO change is pushed.

Object Hierarchy Tree Map — Planning

Click a node to jump to its form.

  1. 4.1 Reserve unique per-site TEP pools, O-UTEP, O-MTEP and BGP-EVPN router-IDs, and keep fabric ASNs distinct for inter-site eBGP EVPN.
  2. 4.2 Allocate VLAN-4 point-to-point subnets for every spine–ISN link and the ISN core, and confirm end-to-end MTU is at least 9150 bytes.

5. Design Patterns (Each with its Ansible Playbook)

Stretched and site-local objects, shared services, inter-site L3Out, and Multi-Site combined with Multi-Pod. Each form emits its own cisco.mso playbook.

Design Pattern Tree Map

Click a pattern to open its playbook form.

  1. 5.1 Create the stretched tenant, schema, template and VRF on both sites.
  2. Choose the BD stretch mode: 5.2 with inter-site BUM (HER on the ISN) or 5.3 unicast-only / WAN-optimised.
  3. 5.4 Keep site-specific applications in a site-local template that is not associated to the peer site.
  4. 5.5 Expose common services from a shared-services tenant and contract.
  5. 5.6 Add an inter-site L3Out and external EPG in the stretched VRF, with site-local physical L3Outs.
  6. 5.7 If a site is itself Multi-Pod, register it as one NDO site and keep IPN and ISN addressing distinct.

6. Nexus ISN Switch Configs (NX-OS CLI & Ansible cisco.nxos)

Build the inter-site underlay on NX-OS: features, VLAN-4 subinterfaces, OSPF, QoS, and a read-only verification form that explains why PIM is usually not required.

ISN Architecture Tree Map

Click a node to jump to its CLI + Ansible form.

  1. 6.1 Enable OSPF, set jumbo MTU and create VRF ACI-ISN with a loopback router-ID. Do not enable PIM by default.
  2. 6.2 Build VLAN-4 routed subinterfaces toward every ACI spine, MTU 9150+, no IP redirects.
  3. 6.3 Enable OSPF Area 0 in point-to-point mode on those subinterfaces and the ISN core link.
  4. 6.4 Trust DSCP and preserve CS6 control-plane markings.
  5. 6.5 Verify OSPF and MTU, and only consider PIM if a native-multicast BUM design has been validated.

7. Day 1 — Nexus Dashboard, Site Onboarding & NDO Infra

Bring up the Nexus Dashboard cluster (verify after the official ISO/CIMC bootstrap), onboard both APIC sites, document Configure Infra (OSPF, overlay TEPs, BGP), and create the first schema and template.

Day 1 Tree Map

  1. 7.1 Bootstrap the ND cluster from the official ISO/CIMC procedure, then verify it with cisco.nd.nd_version.
  2. 7.2 Onboard Site 1 and Site 2 with cisco.mso.mso_site and placeholder APIC credentials.
  3. 7.3 Review the intended Configure Infra payload (OSPF, O-UTEP, O-MTEP, BGP ASNs) and commit it in NDO or your automation role after a self-hosted dry run.
  4. 7.4 Create the first schema and stretched template and associate both sites, leaving objects for Day 2.

8. Day 2 — Tenants, Schemas, Objects & Template Deploy

Add or update tenant, schema, VRF, bridge domain, EPG and contract objects, then deploy the template to both sites with cisco.mso modules.

Day 2 Tree Map

  1. 8.1 Ensure the tenant exists on both sites.
  2. 8.2 Ensure the schema, template and site associations exist.
  3. 8.3 Add the VRF, then 8.4 the bridge domain and 8.5 the application profile and EPG.
  4. 8.6 Create the filter and contract and bind provider/consumer EPGs.
  5. 8.7 Deploy the template to both sites and query deploy status. In CI this still sits behind lint, dry-run and approval.

BAU & LCM Tree Map

  1. 9.1 Take a read-only health snapshot of NDO sites and ND version on a regular cadence.
  2. 9.2 Follow the upgrade order ND/NDO → APIC per site → switches → ISN. Fill sourced target versions when you have them.
  3. 9.3 Keep off-cluster ND/NDO backups plus per-site APIC exports.
  4. 9.4 For RMA, record serials first, then decommission and rediscover with the same node ID.
  5. 9.5 Review TEP and scale headroom. Leave EoL dates as not collected until a Cisco notice is sourced.

10. Troubleshooting (Show Commands & Read-Only Playbooks)

Diagnostic forms only: inter-site EVPN, ISN OSPF, MTU, template deploy failures and the NDO consistency checker. Nothing in this section deploys or undeploys a template.

Troubleshooting Tree Map

  1. 10.2 Confirm ISN OSPF adjacencies and 10.3 jumbo DF-bit ping before chasing overlay symptoms.
  2. 10.1 Check inter-site MP-BGP EVPN on the spines (peers, EVPN routes, router-IDs).
  3. 10.4 Inspect template deploy status without retrying the deploy from this form.
  4. 10.5 Run the NDO consistency checker and compare schema intent with each site APIC.
