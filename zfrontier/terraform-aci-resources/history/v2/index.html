Terraform ACI Resource and Data Source Catalogue

v2 · 26 Nov 2026, 8:48 PM AEDT

Every resource and every data source in the CiscoDevNet/aci Terraform provider (2.21.0: 348 resources and 358 data sources, 706 catalogue entries), taken from terraform providers schema -json and the provider docs at the same tag. Each entry has its own YAML data model in models/ and a numbered sample tf/NNN_*.tf that reads it with yamldecode(file(...)). Numbers follow chronological fabric build order across the whole tree: system and fabric, access policies, tenant networking, applications, L4–L7, Multi-Pod / Multi-Site / Cloud, monitoring, utilities. Each data source follows its resource. Attribute names are exactly the schema’s. Nothing here is invented.

Credential-safe by design: this page is a static catalogue and never contacts an APIC. The provider block reads var.apic_url, var.apic_username and var.apic_password; terraform.tfvars.example holds the placeholder {{ apic_password }}. Secret attributes in models are {{ placeholders }} only. Do not commit real passwords. A live terraform plan belongs on a self-hosted runner that can reach your APIC.

Models, tf files and combined config

All 706 models and sample files are published as real files, plus a combined configuration that validates every one of them.

  • Provider and versions: providers.tf (CiscoDevNet/aci pinned to 2.21.0)
  • Variables: variables.tf and terraform.tfvars.example
  • Combined config: main.tf (module ./tf: every sample in build order, for validation; do not apply as-is)
  • Combined sample data model: sample/aci-model.yml
  • Per-item models: models/<name>.yml (data sources are data_<name>.yml)
  • Per-item samples: tf/<NNN>_<name>.tf

Validate locally (no APIC needed):

terraform init -backend=false
terraform fmt -check -recursive
terraform validate

Grouping and value rules

  • Group = the provider docs subcategory of each item, mapped to the nine build stages (listed under each group). One explicit exception: aci_tenant is filed under Application Management in the docs but is built first in group 3.
  • Order inside a group = docs subcategory order, then DN depth (from the documented DN format, or one level below the parent object referenced in the docs example), then name.
  • Model values: attributes required by the schema (or set in the docs minimal example) take the literal from the docs Example Usage. References to another object become REPLACE_ME with the referenced type in a comment. Every other attribute is null (omit, provider default).
  • Computed-only attributes are listed in each model header as exported attributes, not as inputs.

Gaps and not collected

  • APIC class is not collected for 452 of 706 items and DN for 470: the provider docs for those (mostly older SDKv2 resources) do not state an API class or DN format.
  • No docs page at this tag, so placed in group 9 Other: aci_bgp_route_control_profile, aci_fabric_if_pol, aci_interface_fc_policy, aci_miscabling_protocol_interface_policy, aci_port_security_policy, aci_rest.
  • Marked deprecated in the schema: aci_bgp_route_control_profile, aci_fabric_if_pol, aci_interface_fc_policy, aci_miscabling_protocol_interface_policy, aci_port_security_policy, aci_spine_port_selector, aci_vrf_snmp_context_community, data.aci_bgp_route_control_profile, data.aci_fabric_if_pol, data.aci_interface_fc_policy, data.aci_miscabling_protocol_interface_policy, data.aci_port_security_policy, data.aci_spine_port_selector, data.aci_vrf_snmp_context_community.
  • REPLACE_ME values (1305 in total) are references to another object in the docs example (for example parent_dn = aci_tenant.example.id). Set them to that object’s DN, or swap the model value for a Terraform reference in your own module.
  • Two files carry a _file suffix (*_override_file.tf) because Terraform treats any file ending _override.tf as an override file.
  • Nothing was applied to an APIC. Validation is terraform validate only; live plan/apply needs a self-hosted runner that can reach the APIC.

Approval email templates 348

Every item on this page has a click-to-approve provisioning approval email in the ACI NaC Pipeline layout: status banner, six-stage pipeline, context box, Approve and Deny buttons (a reply to 179172@gmail.com with APPROVE or REJECT), an original topology and logical view, design values and a pre-test summary. They are templates built from the example values here. Nothing is sent or applied, and pre-test, health and fault results are marked not collected.
