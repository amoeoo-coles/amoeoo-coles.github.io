MCP for ACI

MCP for ACI

MCP servers that speak the APIC REST API. There is no Cisco-official, productised ACI MCP server in the documentation I checked. The projects below are community or independently published servers; the CiscoDevNet one is explicitly “not officially supported by any Cisco Business or Technical entity.”

Project facts on this page were checked on 10 Nov 2026 (Australia/Melbourne) against the live GitHub or docs URLs below. Star counts are what the GitHub API returned that day. Nothing here was invented, and no write was sent to any controller.

Verified projects

CiscoDevNet/mcp_server_cisco_aci_community

Community FastMCP server in the Cisco DevNet GitHub org. Also listed on Cisco Code Exchange under the older name cisco_aci_mcp_community, which redirects to this repo. GitHub · Code Exchange. Python. 4 stars, last push 8 Jul 2026 (checked 10 Nov 2026). License SPDX: NOASSERTION. Not archived.

  • Transport: stdio (scripts/server.py; VS Code manages the process via mcp.json).
  • Auth to APIC: cookie session via aaaLogin. Credentials from scripts/.env as APIC_URL, USERNAME, PASSWORD. Auto re-login on HTTP 403.
  • Tools: the README documents 50 operations. GET tools include: aci_simple_test, aci_tenants_get, aci_application_profiles_get, aci_endpoint_groups_get, aci_bridge_domains_get, aci_contexts_get, aci_subnets_get, aci_contracts_get, aci_contract_subjects_get, aci_filters_get, aci_filter_entries_get, aci_endpoints_get, aci_faults_get, aci_fabric_nodes_get, aci_fabric_health_get, aci_fabric_links_get, aci_physical_interfaces_get, aci_ethernet_interfaces_get, aci_vlan_pools_get, aci_domains_get, aci_critical_faults_get, aci_l3_outside_get, aci_external_networks_get, aci_bgp_peers_get, aci_get_operations_summary. Write tools include: CREATE: aci_tenant_create, aci_vrf_create, aci_bridge_domain_create, aci_application_profile_create, aci_epg_create, aci_contract_create, aci_contract_subject_create, aci_filter_create, aci_filter_entry_create, aci_epg_contract_provider_bind, aci_epg_contract_consumer_bind, aci_epg_domain_bind, aci_subnet_create, aci_l3out_create, aci_external_epg_create, aci_vlan_pool_create, aci_physical_domain_create, aci_create_3tier_app, aci_create_web_app_stack. DELETE: aci_tenant_delete, aci_epg_delete, aci_contract_delete.
  • Read vs write: mixed. Use only the GET tools against AOAPIC, and a read-only APIC user. Do not run the CREATE, DELETE or composite deploy tools.

k3l0-dev/niwashi-mcp

Schema-driven FastMCP server: it reads a bundled ACI object-model catalogue rather than hard-coding classes, and is published on PyPI. GitHub · PyPI. Python 3.12+, installable with uvx niwashi-mcp. 1 star, last push 3 Nov 2026 (checked 10 Nov 2026). Actively maintained relative to the others. License SPDX: NOASSERTION.

  • Transport: HTTP, default http://127.0.0.1:8000/mcp (loopback only unless MCP_HOST and MCP_API_KEYS are set). Clients that only launch a local command can use the mcp-remote stdio bridge.
  • Auth: to the APIC, APIC_HOST / APIC_USER / APIC_PASSWORD (and optional APIC_VERIFY_SSL). To the MCP HTTP endpoint, bearer or X-API-Key via MCP_API_KEYS.
  • Tools (exactly five, as documented): search_classes, get_schema, query, get_by_dn, count.
  • Read vs write: the documented tool surface is query, schema and count only. I did not find create or delete tools in the README's five-tool list, which makes this the best match for the “APIC is read-only” rule, provided the APIC account itself is read-only.

beletea/apic-mcp-server

Independent Python MCP server with tenant and fabric analysis, contract-deny logs and PSIRT lookups. GitHub. Python, MIT. 3 stars, last push 1 Aug 2025 (checked 10 Nov 2026). Not archived, but not recently pushed.

  • Transport: stdio as documented in .vscode/mcp.json (uv run --with mcp mcp run <path-to-apic_mcp_server.py>). The README also mentions an HTTP status URL at http://localhost:5000/mcp/status.
  • Auth: APIC_URL, APIC_USERNAME, APIC_PASSWORD, optional APIC_VERIFY_SSL, plus optional PSIRT API settings.
  • Documented tools: authenticate_apic, get_apic_status, logout_apic, get_tenants, get_fabric_nodes, search_objects_by_name, get_application_profiles, get_epgs, get_bridge_domains, get_vrfs, get_contracts, get_denied_logs_for_tenant, get_contract_denies_for_tenant, get_contract_permit_logs_for_tenant, fetch_apic_class, get_node_interface_status, verify_apic_vulnerability, check_cisco_aci_switches_psirt, get_apic_field_notices, get_nexus_9000_field_notices, create_tenant_analysis_document, and the write tools create_apic_object / delete_apic_object (the README describes a preview-and-confirm workflow).
  • Read vs write: mixed. Leave the create and delete tools unused against AOAPIC.

jim-coyne/ACI_MCP

Independent Node.js server (GitHub also accepts jim-coyne/aci_mcp; same repository). GitHub. JavaScript (Node 18+). 2 stars, last push 21 Nov 2025 (checked 10 Nov 2026). No license file advertised in the GitHub API. Appears to have been published in a single day and not pushed since.

  • Transport: launched with npm start after npm run build. The README does not name stdio or HTTP; treat it as a locally launched process and confirm the transport before relying on it.
  • Auth: username/password (ACI_APIC_URL, ACI_USERNAME, ACI_PASSWORD) or certificate (ACI_CERT_NAME, ACI_PRIVATE_KEY_PATH). Optional ACI_TOOL_MODE=core|all and a tool whitelist in aci-mcp-config.json.
  • Documented tools: list/get/create/update/delete for tenants, application profiles, EPGs, bridge domains, VRFs and contracts, plus list_filters, create_filter, delete_filter, get_endpoint_group_stats, get_fabric_health, list_faults, get_fault_summary, list_nodes, get_node_health, list_interfaces, get_interface_stats, get_system_info. The README says the default “core” mode is 35 tools and “all” is 50+.
  • Read vs write: mixed. Restrict the allow-list to the list/get/health tools for AOAPIC.

Connecting to AOAPIC (Always-On APIC)

Aung's DevNet Always-On APIC is the sandbox already used elsewhere on this site as AOAPIC, at https://sandboxapicdc.cisco.com. Put the hostname in an environment variable. Use a read-only APIC username and password from the current DevNet sandbox page — Cisco rotates those credentials, so they are not written here. Do not POST or DELETE anything on this shared fabric.

env
# Placeholder names only — never put a real password or token in git or in chat.
APIC_URL=https://sandboxapicdc.cisco.com
APIC_USERNAME=your-readonly-username
APIC_PASSWORD=your-readonly-password
# Some projects use USERNAME/PASSWORD or APIC_USER instead of APIC_USERNAME.

Example VS Code or Cursor mcp.json for a stdio server (paths and env-var names adjusted to the project you pick):

mcp.json
{
  "servers": {
    "aci-mcp": {
      "type": "stdio",
      "command": "python3",
      "args": ["/absolute/path/to/scripts/server.py"],
      "env": {
        "APIC_URL": "https://sandboxapicdc.cisco.com",
        "USERNAME": "${APIC_USERNAME}",
        "PASSWORD": "${APIC_PASSWORD}"
      }
    }
  }
}

For niwashi-mcp, which listens on HTTP:

bash
# niwashi-mcp (HTTP). Bind stays on loopback unless you also set MCP_API_KEYS.
export APIC_HOST=sandboxapicdc.cisco.com
export APIC_USER=your-readonly-username
export APIC_PASSWORD=your-readonly-password
uvx niwashi-mcp
# MCP endpoint: http://127.0.0.1:8000/mcp

Example prompts

prompts
Show me the tenants on this APIC and the fault count for each.
List the bridge domains and subnets in tenant Test100 (read only).
What is the fabric health score, and which nodes have critical faults?
Search the ACI object model for the class that represents a contract subject, then query how many exist (niwashi-mcp).

Security notes

Read-only by default. Point any server at a least-privilege account. Prefer servers (or tool allow-lists) that only expose GET or query tools. Standing rule on this site: the APIC is read-only — do not create, bind, deploy or delete policy on AOAPIC or any other APIC from an assistant.

Write approval. If a project also ships create, update or delete tools, leave them disabled unless Aung has approved a specific change, and then only against a sandbox or demo he has named. Never commit credentials. Use placeholder environment variables as shown below; rotate any key that has been pasted into a chat or a ticket.

For ACI, niwashi-mcp's documented five-tool surface is the closest fit to a read-only assistant. If you use a mixed server, whitelist only the GET, list or query tools and a read-only APIC login.
