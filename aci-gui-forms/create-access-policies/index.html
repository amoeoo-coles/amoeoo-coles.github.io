Create Access Policies

VLAN pool, physical domain, AAEP, interface policy group/profile and switch profile.

GUI: Fabric›Access PoliciesClass
fvnsVlanInstPphysDomPinfraAttEntityPinfraAccPortGrpinfraNodeP

Access policies are a chain, not one dialog. A VLAN pool is referenced by a physical (or routed) domain; the domain is attached to an AAEP; an interface policy group uses that AAEP; an interface profile selects ports and binds the policy group; a switch profile selects leaf nodes and attaches the interface profile. Until the chain is complete, an EPG cannot be deployed on a leaf port.

The rest of the chain

  • Physical domain (physDomP, uni/phys-{name}) — Fabric > Access Policies > Physical and External Domains > Physical Domains. Bind the VLAN pool with infraRsVlanNs. NaC physical_domains.
  • AAEP (infraAttEntityP, uni/infra/attentp-{name}) — Fabric > Access Policies > Global > Attachable Access Entity Profiles. Attach one or more domains with infraRsDomP. NaC aaeps.
  • Interface policy group (infraAccPortGrp for an access port, or infraAccBndlGrp for a PC/vPC) — Fabric > Access Policies > Interfaces > Leaf Interfaces > Policy Groups. Point it at the AAEP and at link-level policies (speed, CDP, LLDP, MCP, and so on).
  • Interface profile (infraAccPortP) — Interfaces > Leaf Interfaces > Profiles. Port selectors (infraHPortS + infraPortBlk) bind a range of ports to the policy group via infraRsAccBaseGrp.
  • Switch profile (infraNodeP) — Switches > Leaf Switches > Profiles. Node selectors name the leaf IDs; the profile associates the interface profile(s).

Recipe steps

  1. Create a VLAN pool and at least one VLAN range (encap block).
  2. Create a physical domain and associate the VLAN pool.
  3. Create an AAEP and attach the physical domain (and any routed or VMM domains the ports will carry).
  4. Create an interface policy group that uses the AAEP.
  5. Create an interface profile whose port selectors use that policy group.
  6. Create a switch profile that selects the leaf nodes and attaches the interface profile.

NaC YAML

Keys checked against the local Cisco NaC access-policy modules: vlan_pools (allocation, ranges), physical_domains, aaeps, leaf_interface_policy_groups, leaf_interface_profiles, leaf_switch_profiles. Example values below use the AOAPIC LAB-VLAN / LAB-Server / LAB-AAEP names; the interface and switch profile names are an illustrative example.

YAML
apic:
  access_policies:
    vlan_pools:
      - name: LAB-VLAN
        allocation: static          # fvnsVlanInstP allocMode
        ranges:
          - from: 97
            to: 100
            allocation: static      # fvnsEncapBlk
            role: external
    physical_domains:
      - name: LAB-Server
        vlan_pool: LAB-VLAN
        vlan_pool_allocation: static
    aaeps:
      - name: LAB-AAEP
        physical_domains: [LAB-Server]
        infra_vlan: false
    leaf_interface_policy_groups:
      - name: Leaf101_Access
        aaep: LAB-AAEP
        # plus link, CDP, LLDP, MCP policies as required
    leaf_interface_profiles:
      - name: Leaf101_IntProf
        selectors:
          - name: eth1-1
            policy_group: Leaf101_Access
            port_blocks:
              - from_card: 1
                from_port: 1
                to_port: 1
    leaf_switch_profiles:
      - name: Leaf101
        selectors:
          - name: Leaf101
            node_blocks:
              - from: 101
                to: 101
        interface_profiles: [Leaf101_IntProf]
