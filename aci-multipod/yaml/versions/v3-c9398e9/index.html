NaC YAML

The configuration white paper never shows YAML. The block below is a faithful conversion of the GUI and NX-OS it does show into the public Network-as-Code (nac-aci) data model. Every address is the paper’s demo value. Spine node_ids are marked REPLACE because the paper publishes names and EVPN router IDs, not numeric node IDs.

Example only. This is not a payload to POST at an APIC, and it is not taken from a live fabric. Review every address before you reuse it. No passwords from the paper are included.

Converted YAML

YAML (converted from GUI/CLI)
# Network-as-Code (nac-aci data model) converted from
# Cisco ACI Multi-Pod Configuration White Paper c11-739714
# (updated 21 September 2021).
#
# The paper shows APIC GUI / setup-script steps and Nexus OS CLI.
# This file restates those objects in the public nac-aci schema
# (apic.pod_policies, apic.fabric_policies.external_connectivity_policy,
#  apic.access_policies, apic.tenants[].l3outs with vlan + svi:false =
#  a routed sub-interface). Schema references:
#  https://netascode.cisco.com/docs/data_models/apic/pod_policies/pod_setup/
#  https://netascode.cisco.com/docs/data_models/apic/fabric_policies/ext_conn_policy/
#  https://netascode.cisco.com/docs/data_models/apic/tenants/l3out/
#
# Example-only: addresses and names are the paper's dp2-fabric lab.
# Do not apply this file to a live fabric without replacing every value.
# The paper's administrator password is omitted on purpose.
# Numeric spine node IDs are not published in the paper (only names
# dp2-p1-s1 / dp2-p1-s2 / dp2-p2-s3 / dp2-p2-s4 and EVPN RIDs).
# node_id values below are labelled REPLACE.

---
apic:
  fabric_policies:
    # show bgp l2vpn evpn summary vrf overlay-1 on dp2-p1-s1:
    # "local AS number 65000"
    fabric_bgp_as: 65000
    external_connectivity_policy:
      name: default
      fabric_id: 1
      # Wizard default, "strongly recommended" for up to three pods.
      peering_type: full_mesh
      # Community/route-target is auto-assigned by the wizard; the
      # nac-aci default is extended:as2-nn4:5:16 if you must set one.
      routing_profiles:
        - name: pod1-spine-ipn
          # Paper: 192.168.1.0/24 used for Pod1 spine-to-IPN links.
          subnets:
            - 192.168.1.0/24
        - name: pod2-spine-ipn
          subnets:
            - 192.168.2.0/24
    pod_profiles:
      - name: default
        selectors:
          - name: default
            type: all

  pod_policies:
    pods:
      - id: 1
        tep_pool: 10.111.0.0/16
        external_tep_pools:
          # Inferred from advertised prefix 192.168.10.0/24 and
          # EVPN RIDs 192.168.10.3 / 192.168.10.4. Mask /24 is
          # inside the paper's required /22-/29 range.
          - prefix: 192.168.10.0/24
            reserved_address_count: 4
      - id: 2
        tep_pool: 10.112.0.0/16
        external_tep_pools:
          # Wizard text: "A separate External TEP pool 192.168.20.0/24
          # can be used for Pod2."
          - prefix: 192.168.20.0/24
            reserved_address_count: 4

  access_policies:
    vlan_pools:
      - name: vlan-ipn
        allocation: static
        ranges:
          - from: 4
            to: 4
            allocation: static
    routed_domains:
      - name: l3dom-ipn
        vlan_pool: vlan-ipn
    aaeps:
      - name: aaep-ipn
        routed_domains:
          - l3dom-ipn
    spine_interface_policy_groups:
      - name: spine-ipn
        aaep: aaep-ipn
    # Appendix: ports 8/31 and 8/32 facing the Nexus 7000.
    # LLDP table: each Pod 1 spine neighbour is Eth8/32.
    # Pod 2 may use different ports; the paper says to build a
    # separate profile if they do not match.

  tenants:
    - name: infra
      policies:
        ospf_interface_policies:
          - name: ipn-p2p
            network_type: p2p
            # Paper: set ACI MTU to inherit so it matches the
            # IPN interface MTU of 9150. Do not set the OSPF
            # policy MTU above 9000.
            mtu_ignore: false
      l3outs:
        - name: Multi-Pod
          vrf: overlay-1
          domain: l3dom-ipn
          multipod: true
          ospf:
            area: 0.0.0.0
            area_type: regular
            policy: ipn-p2p
          nodes:
            # REPLACE node_id — paper name dp2-p1-s1, EVPN RID 192.168.10.3
            - node_id: 201
              pod_id: 1
              router_id: 192.168.10.3
              interfaces:
                - node_id: 201
                  module: 8
                  port: 32
                  vlan: 4
                  svi: false
                  ip: 192.168.1.0/31
                  mtu: inherit
                  description: to dp2-p1-ipn-1 Eth1/7.4
            # REPLACE node_id — paper name dp2-p1-s2, EVPN RID 192.168.10.4
            - node_id: 202
              pod_id: 1
              router_id: 192.168.10.4
              interfaces:
                - node_id: 202
                  module: 8
                  port: 32
                  vlan: 4
                  svi: false
                  ip: 192.168.1.4/31
                  mtu: inherit
                  description: to dp2-p1-ipn-1 Eth1/8.4
            # REPLACE node_id — paper interface description dp2-p2-s3,
            # EVPN RID 192.168.20.3 (peer of 192.168.10.3)
            - node_id: 203
              pod_id: 2
              router_id: 192.168.20.3
              interfaces:
                - node_id: 203
                  module: 1
                  port: 32
                  vlan: 4
                  svi: false
                  ip: 192.168.2.0/31
                  mtu: inherit
                  description: to dp2-p2-ipn-1 Eth2/7.4
            # REPLACE node_id — paper interface description dp2-p2-s4,
            # EVPN RID 192.168.20.4
            - node_id: 204
              pod_id: 2
              router_id: 192.168.20.4
              interfaces:
                - node_id: 204
                  module: 1
                  port: 32
                  vlan: 4
                  svi: false
                  ip: 192.168.2.4/31
                  mtu: inherit
                  description: to dp2-p2-ipn-1 Eth2/8.4

The matching NX-OS for the IPN devices stays on IPN configuration, because those VRF, OSPF, PIM and DHCP-relay statements are not APIC objects.
