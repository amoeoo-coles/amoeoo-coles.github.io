Physical rack

Physical rack

A rack elevation of the ACI spine-leaf fabric next to a four-node Azure Local cluster, plus an optional remote NX-OS VXLAN EVPN site reached through dedicated Border Gateways. Port roles follow the white paper. Anything the paper does not name is marked as an example.

Example values. Leaf nodes 101 and 102 and interfaces ethernet1/11-12 are the paper’s Table 4 example (two servers). HCI-03, HCI-04 and ports ethernet1/13-14 extend that pattern to a four-node cluster so the drawing matches a typical small Azure Local instance. Spine, border-leaf and BGW node IDs are not published in the Azure Local paper.

What the paper specifies

  • Each UCS C240 M6/M7 Azure Local server connects to a pair of Nexus 9000 ToR switches with dual 100GbE links.
  • The NVIDIA ConnectX-6X dual-port 100GbE NIC (the paper’s wording) is required. Cisco VIC is not an option in that document. Microsoft requires every server node to be configured the same. Up to 16 servers per cluster.
  • Microsoft recommends a 10 GbE or faster network with RDMA.
  • The two server-to-leaf links are individual connections, not a port-channel or vPC.
  • The ToR pair does not have to be dedicated to Azure Local.
  • ToR switches are configured for an MTU of 9216 bytes. Endpoints control the packet MTU they send.
  • CIMC / physical server management uses a dedicated 1GbE link to an out-of-band management switch.
  • The ACI fabric in Figure 14 has two pairs of leaf nodes and two spine nodes, controlled by an APIC cluster. One leaf pair is the Azure Local ToR; the other pair is the border leaves with the L3Out toward external routers.
  • APIC can connect to leaves directly or through the Layer 3 network via the spines.

Source: Cisco Azure Local / Nexus 9000 white paper (ACI and NX-OS modes), Physical Architecture, Figures 1, 5 and 14–15, Table 4

Switch software that Microsoft lists

Microsoft’s physical network requirements list Cisco Nexus 9300-EX, FX, FX2, FX3, GX and GX2 as validated for management, storage and compute (including SDN) when they run NX-OS 10.3(2)F or later, or ACI 6.0(3e) or later. That matches the white paper’s executive summary (ACI 6.0(3e) and NX-OS 10.3(2)F). Table 3 of the paper, which records what the authors tested, lists APIC 6.0(3e), ACI switches 16.0(3e), NDFC 12.1.3b and NX-OS 10.2(3F) on the ToRs — a slightly older NX-OS train than the “support begins at 10.3(2)F” statement.

Source: Microsoft Learn: Physical network requirements for Azure Local, Validated network switches, Cisco 24H2 and 23H2 · Source: Cisco Azure Local / Nexus 9000 white paper (ACI and NX-OS modes), Executive Summary and Table 3

Optional BGW rack role

If you also interconnect this ACI fabric with a standalone NX-OS VXLAN EVPN site, add a dedicated BGW leaf pair. Those nodes are not the Azure Local ToRs and not the tenant L3Out border leaves. They connect north to an IP-only intersite network; they do not connect back-to-back to the remote NX-OS BGWs. Hardware: Nexus 9000 FX or later with 32 GB of RAM; FX2 is not supported.

Source: Cisco APIC L3 guide 6.2(x): Guidelines and limitations for ACI border gateways, dedicated nodes, hardware and no back-to-back BGW
