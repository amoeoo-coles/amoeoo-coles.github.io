How the objects relate

  • common / common_VRF — Bridge domains Storage-A and Storage-B have no subnet, custom forwarding, flood for unknown unicast, and unicast routing disabled. Bridge domain Mgmt has anycast gateway 10.1.1.254/24.
  • EPG Mgmt (VLAN 1600) — QoS class Level3. The paper prefers a native VLAN for management and also supports tagged. It consumes the shared L3Out contract so hosts can reach external networks.
  • EPG Storage-A and Storage-B — use the custom QoS policy Storage_and_Cluster. Because storage traffic stays inside its BD, the paper says there is no need for a contract with another EPG.
  • HCI_tenant1 / VRF1 / BD1 — anycast gateway 192.168.1.254/24. Application profile AP1 contains EPG Web (VLAN 1611) and EPG App (VLAN 1612), both QoS Level3.
  • Contracts — Web-to-App is defined in the tenant with scope VRF. Allow-Shared-L3Out is provided by common (global) so the tenant EPGs can reach the shared L3Out. The paper lists those contract names but does not publish filter entries, and it does not include the Shared L3Out configuration steps.

Source: Cisco Azure Local / Nexus 9000 white paper (ACI and NX-OS modes), Azure Local ACI Tenant Model Overview, Figure 16, Tables 5 and 6, Configure EPGs

The optional BGW stretch of VRF1 and BD1 toward a remote NX-OS EVPN site does not add extra tenant objects on this diagram. It is a VXLAN stretch attached to those same objects; see the YAML files and logical topology.
