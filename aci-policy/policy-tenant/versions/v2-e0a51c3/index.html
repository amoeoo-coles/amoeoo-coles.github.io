How to read the layers

  • Tenant — the administrative container (Customer / BU / Group). Everything below lives under uni/tn-PolicyTenant. See Tenants.
  • Contexts (VRFs) — two routing tables, Context-1 and Context-2. They do not leak routes to each other unless you build a contract and shared-service leak on purpose. See VRF.
  • Bridge Domains (L2 boundary) — BD1 and BD2 sit under Context-1; BD3 sits under Context-2. Broadcast, unknown unicast and multicast flood inside a BD, not across BDs. See Bridge Domain.
  • IP space(s) — subnets are configured on the BD, not on the EPG. BD1 has Subnet A (10.1.10.1/24) and Subnet B (10.1.20.1/24); BD2 has Subnet D (10.1.30.1/24); BD3 has Subnet B (10.1.20.1/24) and Subnet F (10.2.10.1/24). See Subnet.
  • Why Subnet B can appear in two BDs — BD1 is in Context-1 and BD3 is in Context-2. Overlapping IP space is allowed across VRFs because each context has its own routing table. The same prefix in one VRF would be a conflict.
  • EPGs — groups of endpoints and the policies that define their connection. BD1 holds EPG A and EPG B; BD2 holds EPG C; BD3 holds EPG A, B and C. An EPG is not the flood domain — the BD is. See Endpoint Group.
  • EPGs talk through contracts — the line from EPG B to EPG C crosses BDs (still in the same VRF, so the contract plus routing in Context-1 can connect them). On BD3 the lines are A–B and C–B. See Contract.

NaC YAML for this sample tenant

Example IPs are on the diagram. Contract names match the drawn links. EPG names on BD3 are suffixed so they can live in the same application profile as the BD1/BD2 EPGs (APIC EPG names must be unique inside an AP).

YAML
apic:
  tenants:
    - name: PolicyTenant
      vrfs:
        - name: Context-1
        - name: Context-2
      bridge_domains:
        - name: BD1
          vrf: Context-1
          unicast_routing: true
          unknown_unicast: proxy
          arp_flooding: true
          subnets:
            - ip: 10.1.10.1/24    # Subnet A
              private: true
            - ip: 10.1.20.1/24    # Subnet B in Context-1
              private: true
        - name: BD2
          vrf: Context-1
          unicast_routing: true
          subnets:
            - ip: 10.1.30.1/24    # Subnet D
              private: true
        - name: BD3
          vrf: Context-2
          unicast_routing: true
          subnets:
            - ip: 10.1.20.1/24    # Subnet B again — OK, different VRF
              private: true
            - ip: 10.2.10.1/24    # Subnet F
              private: true
      application_profiles:
        - name: PolicyTenant_AP
          endpoint_groups:
            - name: EPG-A
              bridge_domain: BD1
              contracts:
                providers: [contract-ab]
            - name: EPG-B
              bridge_domain: BD1
              contracts:
                providers: [contract-bc]
                consumers: [contract-ab]
            - name: EPG-C
              bridge_domain: BD2
              contracts:
                consumers: [contract-bc]
            - name: EPG-A-BD3
              bridge_domain: BD3
              contracts:
                providers: [contract-ab-bd3]
            - name: EPG-B-BD3
              bridge_domain: BD3
              contracts:
                consumers: [contract-ab-bd3, contract-cb-bd3]
            - name: EPG-C-BD3
              bridge_domain: BD3
              contracts:
                providers: [contract-cb-bd3]
      contracts:
        - name: contract-bc        # EPG B (BD1) — EPG C (BD2), crosses BDs
        - name: contract-ab        # EPG A — EPG B in BD1
        - name: contract-ab-bd3    # A–B inside BD3
        - name: contract-cb-bd3    # C–B inside BD3
